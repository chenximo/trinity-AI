## 0.1 瘦接口 MVP（推荐 · 16 条可压到 8 条）

> 下面「可合并 / 可砍」不改变业务闭环，只减路由与实现量。  
> **已接前端的 `catalog/excel`** 可保留为 **artifacts 的薄别名**（同一 Service），不必维护两套存储。

| 原接口 | 建议 | 理由 |
|--------|------|------|
| C-01 三条 `catalog/excel` | **实现层合并进 S-05 artifacts**（`kind=catalog-excel`）；路由可保留别名兼容现 Admin | 同是存 xlsx，一套 upsert + download 即可 |
| `GET commercial/latest` | **砍掉** → `GET artifacts?kind=l3a-draft&modality=&latest=1` | latest 只是「取最新一条 meta」，不必单独资源 |
| `GET supply-routes/snapshot` | **不对外暴露**（仅 `generate` Job 内调） | 运营从不单独点 snapshot；手导 xlsx 已被 generate 替代 |
| `GET/PUT matrix` + `POST matrix/confirm` | **合并为 2 条**：`GET matrix` + `PUT matrix`（body 加 `confirm: true` 表示生效） | confirm 不是独立业务对象，少一次往返 |
| `GET archives/{id}` | **砍掉**（MVP） | 列表项带齐 `matrixSnapshot`、artifact id 即可 |
| C-03 `upstream-sources/.../fetch` | **整项延后 P3** | 无 Webhook 接收端；CLI 本地抓价够用 |
| `upstreamFetchWebhookUrl` / `commercialGenerateWebhookUrl` | **MVP 不实现外调** | Backend 内嵌跑 Python 即可；Webhook 以后再加 |

**推荐研发先做的 8 条（+ 可选 3 条 catalog 别名）**

| # | 方法 | 路径 | 覆盖 |
|---|------|------|------|
| 1 | PUT | `/v1/admin/pricing/commercial/artifacts` | 所有 xlsx 上传（含刊例、L3b/L3a、snapshot） |
| 2 | GET | `/v1/admin/pricing/commercial/artifacts` | `?kind=&modality=&latest=1` 列表 / 取最新 |
| 3 | GET | `/v1/admin/pricing/commercial/artifacts/{id}/download` | 统一下载 |
| 4 | POST | `/v1/admin/pricing/commercial/generate` | 触发生成（内嵌 S-01，不暴露 API） |
| 5 | GET | `/v1/admin/pricing/commercial/matrix` | 读矩阵 |
| 6 | PUT | `/v1/admin/pricing/commercial/matrix` | 存草稿；`confirm:true` 写入生效 |
| 7 | POST | `/v1/admin/pricing/commercial/archive` | 归档 |
| 8 | GET | `/v1/admin/pricing/commercial/archives` | 归档列表（含详情字段） |

**兼容现 Admin（P1 可只做别名，逻辑走 1～3）**

| 方法 | 路径 | 行为 |
|------|------|------|
| PUT/GET | `/v1/admin/pricing/catalog/excel` | 转调 artifacts，`kind=catalog-excel` |
| GET | `/v1/admin/pricing/catalog/excel/{modality}/download` | 查该 modality 最新 `catalog-excel` → 302 或流式 `artifacts/{id}/download` |

下文 §2～§4 为**展开契约**；若按瘦接口做，以本节为准排期。

## 1. 共用类型 · 建议存储

```typescript
// pricingOpsApi.ts — C-01 与 S-05 对齐
type PricingBinaryArtifactMeta = {
  id: number;
  kind: string;           // catalog-excel | l3b-draft | l3a-draft | snapshot-routes | …
  modality?: string | null;
  fileName: string;
  sizeBytes: number;
  source: string;
  label?: string | null;
  meta?: Record<string, unknown> | null;
  createdAt: string;
};
```

**建议**：一张 `pricing_binary_artifact` 表 + 对象存储；C-01 与 S-05 共用 Service，`kind` 区分。

**鉴权**：全部 Admin JWT（`Authorization: Bearer`）。Worker 价审后上传 catalog 用 `ADMIN_API_TOKEN`（同 JWT 形态）。

## 2. P1 · C-01 价目预览刊例 Excel

**页面**：`/pricing/catalog`  
**目的**：存 `trinity-pricing-{text|image|video}.xlsx`；价审 Worker 成功后 **异步 PUT**（`source=worker-post-review`），失败 **不挡** 价审 `ready`。

### PUT `/v1/admin/pricing/catalog/excel`

`multipart/form-data`

| 字段 | 必填 | 说明 |
|------|------|------|
| `modality` | 是 | `text` \| `image` \| `video` |
| `file` | 是 | `.xlsx` |
| `source` | 否 | `manual` \| `worker-post-review` \| `cli` |

同 modality **upsert**（覆盖当前版）。响应 `PricingBinaryArtifactMeta`，`kind=catalog-excel`。

### GET `/v1/admin/pricing/catalog/excel`

返回数组，每 modality 至多一条；无数据 `[]`（不要 404）。

### GET `/v1/admin/pricing/catalog/excel/{modality}/download`

200 = xlsx 二进制；404 = 未登记。

**验收**：Admin 手传可预览下载；Worker PUT 后列表有 `worker-post-review`。

## 3. P1 可选 · C-03 上游抓价

**页面**：`/pricing/catalog` 上游行「获取价格」

### POST `/v1/admin/pricing/upstream-sources/{vendorCode}/fetch`

**请求体**：

```json
{ "sourceUrl": "https://…", "vendorName": "百炼" }
```

**响应**（对齐 `PricingUpstreamFetchResult`）：

```json
{
  "vendorCode": "bailian",
  "status": "accepted",
  "message": "已投递抓价任务",
  "sourceUrl": "https://…",
  "webhookConfigured": true,
  "logId": 42
}
```

**服务端行为**：

1. 读 `ops-settings.upstreamFetchWebhookUrl`  
2. 若已配置 → POST Webhook（body 含 `vendorCode`、`sourceUrl`、`fetchLogId` 等）→ 异步跑已有 `pricing:supplier:*` CLI  
3. 若未配置 → 返回 `webhookConfigured: false`，提示未配置  
4. **只更新上游数据，不写 `/v1/prices`**

**验收**：配置 Webhook 后点「获取价格」→ `accepted`；Job 成功后更新抓取时间（字段自定）。

## 4. P2 · 商务价格（S-01～S-05）

**页面**：`/pricing/commercial`  
**目的**：一键生成 **L3b 对内总册** + **L3a 对外报价表** → 矩阵确认 → 归档下载。**不写** `/v1/prices`。

**生成流程**：

```text
点「生成定价包」
  → S-01 拉线路 snapshot
  → S-02 Job：rebuild_discount_tier_workbook.py → L3b
              build_outward_quote_standard.py → L3a
  → S-05 存 artifacts + S-02 GET latest
  → 页上预览/下载
改矩阵 → S-03 confirm → 再生成
满意 → S-04 归档
```

### S-03 · 公开矩阵

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v1/admin/pricing/commercial/matrix` | 返回 `{ rows, version, editingRows? }` |
| PUT | `/v1/admin/pricing/commercial/matrix` | 保存编辑草稿 `{ rows }` |
| POST | `/v1/admin/pricing/commercial/matrix/confirm` | 写入生效配置，返回 `{ version }` |

**矩阵行结构**（与 Admin 原型 `MatrixRow` 对齐）：`id`、`familyLabel`、`standardGm`、`plus`/`mid`/`growth`/`scale`/`enterprise`（各含 `zhe`、`gm`）。

**硬规则**：对外列仅 **$5k / $10k / $50k**；折底线 **5.5**（0.40 族最深 5.5，0.50 族最深 6.0）。配置真源建议：`trinity-AI/pricing/config/public-ladder-matrix.json`。
