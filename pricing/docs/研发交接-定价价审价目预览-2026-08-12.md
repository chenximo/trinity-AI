## 1. 「定价还没有调」是什么意思

**能生成建议价 ≠ 已经改线上价。**

```text
触发价审 → 出 V2 vs V1 对比确认单 → 【还没做】运营点「确认写价」→ /v1/prices 才变
```

当前生文 V2 包（`listing_v2_intl_first`）快照：

| 指标 | 数量 |
|------|------|
| 生文模型 | 69 |
| V1 vs V2 **一致** | 49 |
| **有偏差** | 12 |
| **只上浮可写回**（L-01 闸） | **1** → `hy-mt2-plus`（入 0.077→0.1，出 0.308→0.4） |
| V2 更低 → **维持 V1、不写回** | 其余偏差项（含 `qwen-max`、`glm-5.2`、`kimi-*` 等） |

**产品侧待做（不是研发 bug）**

1. 打开价格校验 → 审 **将写回 / 维持 V1 / 无草案** 分组（新 UI 见 §4）  
2. 确认是否对 `hy-mt2-plus` 点 **确认写价**（当前唯一默认可写回项）  
3. **待拍板**：`qwen-max` 线上明显高于 V2（+333%），V2 用 `fallback-v1` 未接百炼国际锚 — 是否补 seed / 是否单独调价（见 §6）  
4. 生图 / 生视频：Worker 默认步骤 **仍为空**，尚未进 V2 价审链  

真源 diff：`pricing/output/draft/listing-v2_prices-api-diff.md`

## 7. 联调验收剧本（提测勾选）

### A. 价格校验（不依赖 C-01）

- [ ] Admin 触发生文价审 → 同一 `taskId` → `ready`  
- [ ] 确认单含 V1/V2/diff；汇总见 **1 项将写回**（hy-mt2-plus）  
- [ ] **不点确认** → `GET /v1/prices` 不变  
- [ ] 点确认写价 → hy-mt2-plus 价格变 + 模型「已校验」  
- [ ] 误写可复原（若批次支持）  

### B. 价目预览（依赖 C-01 Backend）

- [ ] Worker 价审成功后日志 `[catalog-sync]` 成功  
- [ ] `GET /v1/admin/pricing/catalog/excel` 返回 text 行  
- [ ] 价目预览可下载/预览，无需手传  
- [ ] catalog 失败时价审仍为 `ready`  

### C. 本地 CLI（开发自检）

```bash
cd trinity-AI
npm run pricing:fetch
npm run pricing:listing:v1v2
npm run pricing:gen-listing-v2
npm run pricing:diff:listing-v2
npm run pricing:emit-review-package
# → pricing/output/review-packages/review-package-text.json
```
