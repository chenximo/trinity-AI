## 0. 一句话

```text
官方锚价 → 进货/成本 → 线上基础刊例 →（对外标准报价 / 商务洽谈折）
→ 客户预充值按绝对价扣费
← 月度：平台成本 vs 上游实付 对账回填
```

Trinity 对客是 **预充值 + 绝对价扣费**（不是中转站额度×倍率制）。详见 [计费方式对比汇总-额度倍率与绝对价.md](./计费方式对比汇总-额度倍率与绝对价.md)。

## 2. 价格层（四层不要混）

口语里的「刊例」要拆开，否则官方价、线上价、销售价、商务折会对不齐。

| 层 | 名称（推荐） | 是什么 | 真源 / 入口 | 谁改 | 对外？ |
|----|--------------|--------|-------------|------|--------|
| **L0** | **官方刊例锚** | 原厂文档价（$/¥·M 等） | `pricing/suppliers/official/` · Skill `trinity-official-pricing` | 跟官网刷新；不手改「冒充官方」 | 不对客当卖价 |
| **L1** | **进货 / 渠道挂牌** | TokenHub、百炼、AIGC 等转售挂牌 | `pricing/suppliers/{渠道}/` | 抓价 Job / 运营核对 | 不对客 |
| **L2** | **线上基础刊例** | Trinity 对客**原价锚**（`/v1/prices`、控制台价目） | 价审确认后写后台；`listing-deploy`；派生规则见 [刊例策略 V1/V2](./刊例策略-V1-V2-国际站优先.md) | **价审 HITL** 后写 | ✅ 基础卖价 |
| **L3a** | **对外标准报价表** | 销售可发的标准档绝对价（规划） | [OUTWARD-QUOTE-AND-SUPPLY-CLASS.md](./OUTWARD-QUOTE-AND-SUPPLY-CLASS.md) | 由 L2 生成；人确认 | ✅ 外发 |
| **L3b** | **商务洽谈价** | 成本折族 × 客户档（Plus…Enterprise） | [`商务洽谈折扣总表.xlsx`](../output/商务洽谈折扣总表.xlsx) · [discount-tier-matrix](../../apps/trinity-product/docs/ai-api-platform/commercial-billing/discount-tier-matrix.md) | 产品/商务策略 | ❌ 整表不外发 |

### 2.1 关系（怎么传导）

```text
L0 官方锚 ──对照──► L1 进货挂牌
         └────────► L2 线上基础刊例（价审：官方 vs 进货 vs 线上）
                         │          ▲
                         │          └── 派生：listing_policy 默认 V2
                         │              （官网国际站优先；否则 V1=国内÷6.5）
                         │              详见 [刊例策略 V1/V2](./刊例策略-V1-V2-国际站优先.md)
                         │
                         ├─► L3a 对外标准报价（建议 = L2 标准档，或经拍板的浅公开价）
                         │
                         └─► L3b 商务折：在 L2 上乘客户档折（看 GM 护栏）
```

**成本折**（供应商给我们的进货折扣族，如 6.5 折线）属于**对内成本锚**，进入交叉线路与商务表，**不是**客户看到的「官网折扣」同一列。

### 2.2 供应三类怎么进价格

| 供应 | 进哪一层 | 对外 |
|------|----------|------|
| 官 Key / 云 MaaS | L1 成本 + 选路；支撑 L2 | 可支撑标准档 / 高可用 |
| 二转 | 仅成本与 failover | **不进** L3a 客户价目 |

详见 OUTWARD 讨论稿。

### 2.3 与「销售刊例价」用词对齐

| 有人口语 | 本文对应 |
|----------|----------|
| 官方刊例价 | **L0** |
| 销售刊例价 / 平台刊例 | 通常指 **L2**；外发材料用 **L3a** |
| 商务报价 | **L3b**（谈判）或 L3a（标准外发）——勿混 |

## 3. 客户侧：结算与扣费（账单系统 · 对客）

| 模块 | 口径 | 真源 |
|------|------|------|
| **结算形态** | 预充值 Credits → 按量扣费 | [billing-strategy-map](../../apps/trinity-product/docs/ai-api-platform/commercial-billing/billing-strategy-map.md) · [商用计费总览](../../apps/trinity-product/docs/ai-api-platform/commercial-billing/) |
| **扣费单价** | 绝对价（$/¥·token 或按次），可叠加合同/档位折 | L2 + L3b；运行时 [计量与计费](../../apps/trinity-product/docs/ai-api-platform/platform/metering-billing.md) |
| **钱包 / 配额 / 计费** | 概念拆分见 Docs | trinity-docs 概念页 |
| **支付** | Stripe 等 MVP；Antom 等通道 | commercial-billing MVP / 支付文 |
| **客户账单** | 充值流水、调用扣费、余额、用量报表 | 控制台 · 运营后台 billing |

**不是**：充值换成抽象「额度点」再乘 NewAPI 三层倍率（见计费方式对比汇总）。

### 3.1 对客账单最小闭环

```text
充值入账 → 余额增加
API 调用 → 计量（token/次）→ 按生效单价算费 → 扣余额
余额不足 → 402 / 拒绝对话
控制台可查：余额、用量、账单明细
```

价格变更：L2 价审写回后，新请求走新价；历史扣费不重算（除非产品另定纠错流程）。

## 4. 成本结算（账单系统 · 对内成本）

「成本结算」= 搞清楚**我们为上游调用付了多少、对应多少 Token**，并和线路成本假设对齐。

| 项 | 说明 |
|----|------|
| **平台侧成本** | 按命中线路、内部成本单价/成本折估算的期间成本与 Token（导出） |
| **上游实付** | 供应商账单/发票实付金额与用量（人工拉取） |
| **线路与成本折** | 后台线路管理 + 商务原底成本折族；交叉表推荐 P1 |
| **选路与毛利** | 对客价（L2/L3）− 实际命中线路成本；建议合格主供内成本优优先，二转不因最便宜而最高优先 |

```text
请求命中线路（官 Key / 云 / 备线）
    → 记平台用量 + 估算成本
月度汇总平台成本/Token
    → 与上游实付核对（§5）
```

工程目录：`pricing/billing-reconciliation/` · Skill `trinity-billing-reconciliation`。

## 5. 对账系统（账单核对柱②）

### 5.1 目标

按月（必要时按日）核对：

| 比对项 | 平台侧 | 上游侧 |
|--------|--------|--------|
| 钱 | 估算/记账成本 USD（及约定汇率） | 实付 USD/CNY |
| 量 | Token / 次 / 秒等 | 账单用量 |

确认后**人手回填**后台「上游实付」；系统不替人拍板。

### 5.2 标准流程

```text
1. 导出平台侧：账单月 × 上游 × 成本 USD × Token…
2. 人拉上游账单副本入库
3. Skill / 脚本出核对报告（差%、归因提示）
4. 人确认 → 回填实付；差大则日结深挖
5. 审计：报告与 notes 留存
```

目录约定见 [billing-reconciliation/README.md](../billing-reconciliation/README.md)。  
已有样例：腾讯 AIGC `2026-06` / `2026-07` notes。

### 5.3 和刊例巡检的边界

| | 刊例治理 ① | 账单核对 ② |
|--|------------|------------|
| 比什么 | 官方锚 vs 进货挂牌 vs **线上刊例** | **平台成本/量 vs 上游实付/量** |
| 频率 | 上新、变价、巡检 | 月度为主 |
| 写什么 | 确认后改刊例 | 确认后填实付 |
| 禁止 | 混成一次任务自动改两边 | 用对账差直接改 L0 官方锚 |

### 5.4 汇率（禁止混用）

| 口径 | 用途 |
|------|------|
| 价目 ÷6.5 | 人民币挂牌写入成本/对比官方 |
| 账单对账 6.5 | 上游 CNY → USD vs 平台成本 USD |
| 充值/付汇市价 | 客户充值与购汇；现金损益附录 |

### 5.5 后台统计基线与环比风控（已拍方向 · 2026-08-03）

> **原则**：**没有一个对账/风控数字是凭空估的**——一律来自运营后台**正式统计**；先多记几个月，再谈阈值。

#### 结论（产品判断）

| 判断 | 说明 |
|------|------|
| ✅ **成立** | 跨上游硬比（总 Token、每百万大致单价）**参考意义有限**——模型结构、计价单位、账期、是否含税/缓存差太大 |
| ✅ **高价值** | **同一上游、不同月份**的结构占比与单价带 → 环比才有「正常带」 |
| ✅ **财务风控** | 占比/单价偏离历史带即预警；上游与模型变多后不可能月月人肉盯，必须阈值告警 |

#### 后台已推进 / 应具备的统计（平台侧真源）

（已与工程对齐加统计；后续对账与告警只读这些字段。）

| 类 | 指标（示例） | 用途 |
|----|--------------|------|
| Token 总量 | 输入 / 输出 / 缓存 及**各自占比** | 结构漂移（如缓存占比骤变） |
| 成本/消耗金额 | 入/出/缓等分项及**占比** | 钱侧结构漂移 |
| 派生 | 有效 $/百万 tokens（分项或综合） | 同上游月度单价带 |
| 维度 | 至少：账单月 × **上游**；（后续）× 模型/模态 | 环比主键 |

#### 参考价值分级

| 对比方式 | 价值 | 用法 |
|----------|------|------|
| 上游 A vs 上游 B 同月 | 低～中 | 仅粗览；不作为主要异常判据 |
| **同一上游 本月 vs 近 N 月** | **高** | 主风控：占比、单价、总量增速 |
| 平台侧 vs 该上游实付账单 | **高** | 柱② 核对主路径（钱/量对齐） |
