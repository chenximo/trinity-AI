## 1. 为什么要做

| 做 | 不做（第一期） |
|----|----------------|
| 每模态两个槽：当前 / 上一版 | 无限历史版本 |
| 确认写价成功才写入 | 价审草稿进版本库 |
| 回退 = 现有 restore + 两槽对调 | 整本 `GET /v1/prices` JSON 覆盖回写 |
| Admin 历史页以两槽为主入口 | 和商务 L3a/L3b 归档混用 |

## 4. 快照内容

与 Admin 已有运维 **catalog-snapshot** 同源（档位库，不是跨服务调 chat 的 `GET /v1/prices`）。

过滤建议：仅启用模型、指定模态、不含停用档。结构至少包含：

```json
{
  "generatedAt": "ISO-8601",
  "filter": { "enabled": "true", "modality": "text" },
  "summary": { "total": 0, "enabled": 0, "disabled": 0 },
  "models": [
    {
      "modelCode": "xxx",
      "displayName": "…",
      "tiers": [
        {
          "chargeUnit": "…",
          "userUnitPriceUsd": 0
        }
      ]
    }
  ]
}
```

前端预览只读 `models[].modelCode` / `displayName` / `tiers[].chargeUnit` / `tiers[].userUnitPriceUsd`。  
`currentModelCount` / `previousModelCount`：优先 `summary.total`，否则 `models.length`。

可选：把写前/写后快照落到价审 artifact（如 `listing-pre` / `listing-post`），并填 apply-batch 已有字段 `pre_snapshot_artifact_id` / `post_snapshot_artifact_id`（现网列在，此前未写入）。

## 5. 轮转规则（必须）

### 5.1 确认写价成功 `POST /v1/admin/pricing/reviews/{id}/confirm`

在 **档位写库成功之后**（现有 `PriceReviewListingWriteService.applyConfirmModels`）：

1. 写前拍一帧 → `pre`；写后再拍 → `post`。
2. 旧 **当前** → **上一版**；若确认前没有当前，则 **上一版 = pre**（`previous_batch_id` 空）。
3. **当前 = post**，`current_batch_id` = 本次 apply-batch id。
4. 幂等 confirm（已有 `idempotencyKey` 直接返回）**不得再轮转**。
5. 写价失败整笔回滚，槽不更新。

### 5.2 回退

**产品入口**（前端已调）：

```http
POST /v1/admin/pricing/listing-live-slots/{modality}/restore
Authorization: Bearer <admin-jwt>
```

行为：

1. 无 `current_batch_id` → 409 `no current listing version to restore`
2. 无 `previous_json` → 409 `no previous listing version`
3. 用 **当前槽的 `current_batch_id`** 走现网 `POST …/review/apply-batches/{batchId}/restore`（按档 `before_json` 复原）
4. 该 restore **成功后** 两槽对调（当前 ⇄ 上一）

现网按 batch 复原仍保留作审计。若复原的 batch **不是** 该模态当前槽的 `current_batch_id`，**不要**对调槽，以免槽和线上不一致。

`restoreEligible`（列表用）：当前槽有 `current_batch_id`、有 `previous_json`、且该 batch `status=applied` 且 `restoreEligible=true`。

## 6. API（与前端契约对齐）

**Base**：`/v1/admin/pricing`  
**鉴权**：与其它价审接口相同，Admin JWT。  
信封：现网 `ApiEnvelope`。

### 6.1 列表（无 snapshot 体，避免三模态大 JSON）

```http
GET /v1/admin/pricing/listing-live-slots
```

固定返回 **三行** `text` / `image` / `video`（无数据也返回空槽，不要 404）。

### 6.2 预览

```http
GET /v1/admin/pricing/listing-live-slots/{modality}?slot=current
GET /v1/admin/pricing/listing-live-slots/{modality}?slot=previous
```

`slot` 缺省 `current`；非法值 400。`snapshot` 只带所请求那一槽的 JSON。

### 6.3 响应体

```typescript
type ListingLiveSlot = {
  modality: string;
  currentAt?: string | null;
  currentBatchId?: number | null;
  currentModelCount?: number | null;
  previousAt?: string | null;
  previousBatchId?: number | null;
  previousModelCount?: number | null;
  updatedAt?: string | null;
  restoreEligible: boolean;
  snapshot?: Record<string, unknown> | null;
};
```

时间字段 ISO-8601 字符串。列表接口 `snapshot` 为 `null`。

### 6.4 回退响应

与现网 `POST …/review/apply-batches/{id}/restore` 相同：`PriceReviewApplyBatch`。

## 7. 验收

1. 某模态第一次 confirm：当前 = 写后快照；上一版 = 写前快照；可预览模型行。
2. 第二次 confirm：上一版变成第一次的当前；当前为第二次写后。
3. 点「回退到上一版」：线上档位回到写前；槽对调；再 GET 列表与预览一致。
4. 草稿 / 未 confirm：**不**改槽。
5. 重复 confirm（同一 idempotencyKey）：槽不二次轮转。
6. 不实现整本 `/v1/prices` 覆盖回写。
