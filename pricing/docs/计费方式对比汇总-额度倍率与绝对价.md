## 0. 一句话结论

```text
预充值 ≠ 额度制。
中转站常见：充钱 → 点数，按 token×倍率扣点（A）。
Trinity：充钱 → 美元/人民币余额，按刊例绝对价扣（B）。
A 在中转圈主流；B 在云/原厂/OpenRouter/ToB 主流。
对外报价表建议继续 B（绝对价），不上倍率作主叙事。
```

## 1. 两种计费分别是什么

| | **A. 额度制 + 倍率** | **B. 预充值 + 绝对价** |
|--|----------------------|------------------------|
| 账户里是什么 | 充钱 → **点数/额度**（积分感） | 充钱 → **USD/CNY 余额** |
| 怎么扣 | `(输入 + 输出×补全倍率) × 模型倍率 × 分组倍率` | 用量 × **$/¥·M（或按次）** |
| 改价方式 | 改倍率表 | 改刊例单价 / 合同折 |
| 价目常见写法 | 模型倍率、分组倍率、折扣列 | 输入/输出绝对价 |
| 典型 | OneAPI / NewAPI 中转站 | 云厂商、OpenRouter、推理云、**Trinity 现状** |

### 1.1 「倍率」和「折扣」同时出现时（APIhub 海外）

海外表里两列**通常不是叠两刀**，而是同一件事的两种写法：

| 列 | 作用 |
|----|------|
| **倍率** | 与分组/系统扣费对齐（运营母语） |
| **折扣** | 对照官网好不好懂；APIhub 表内 ≈ **倍率 ÷ 7**（该表私有刻度） |

例：倍率 1.6 → 折扣约 22.9%；倍率 5.5 → 约 78.6%。

国内块更常直接写卖价 + 折扣，不一定走 ÷7。

### 1.2 「分组倍率 + 充值折」叠两层（KuaiGouAI / AskMind）

与 §1.1 **不同**：这是**真·两层旋钮**。

```text
层① 调用：标准价锚 × 分组倍率（1.2×～3.0×）→ 抬/拉开扣额度
层② 付款：充值金额 7～8.8 折 → 营销「充越多越便宜」
```

代表站：[AskMind 分享首页](https://api.askmind.cn/share/) · [定价](https://api.kuaigouai.com/share/pricing) · [Claude 倍率表](https://api.askmind.cn/share/models/anthropic)  
粗算与样例见竞品汇总 **§1.2 / §8**。

**Trinity**：不要对外复制「先抬倍率再喊充值折」；继续绝对价刊例 + 预充值达档。

### 1.3 「RMB/刀」与「$/M」不要横比（奇点）

奇点产品目录混用：

| 单位 | 含义 |
|------|------|
| **RMB/刀** | 充值换美元额度的汇率（例 1.25） |
| **倍率** | 用量相对官方的倍数 |
| **x 折** | 相对官方折扣 |
| **元/次·秒** | 图/视频 |

相对 Trinity 内部折算基准 **6.5**：有效换刀折 ≈ `刀价/6.5`（1.25 → 约 1.9 折）。  
详例见竞品汇总 **§1.3 / §9**。

### 1.4 APIhub 报价表还说了什么 / 没说什么

**有写：**

- 标题：常用模型报价（核对官网价）
- 模型 × **分组（线路）** → 倍率 / 按次价 / 折后价
- 文本常写「按分组确定倍率」
- 免责：价可能变动以站点为准；分组不同价不同；**不含税**，专票加 6 个点

**没写：**

- 多条线路**混合/自动切换**时按哪个价扣  
（实际产品里通常是 Key **绑定某一分组**，按该组扣，而不是一张表写清混合协议）

→ 与 Trinity「交叉多线路 + 对内选路、对客稳定标价」可对照：表列的是**各线路标价**，不是混合计费说明书。

## 2. 额度制像不像积分？具体流程

**很像积分制**：先买一包点，再按规则扣点。

```text
① 充值：付 $100（或人民币）
② 到账：换成额度（点）
   例（NewAPI 常见口径，非 APIhub Excel 原文）：500,000 额度 = $1
   → $100 → 50,000,000 额度
③ 调用：按 token × 倍率扣额度
④ 界面可再显示成「约剩 $xx」
⑤ 额度≈0 → 再充
```

**骨子里改价改的是倍率和点数**；看起来可以有美元余额。

### 2.1 举例：$100 + APIhub 口径下的 Claude 类

官网参考（1 倍率≈官网）：入 **$3** / 出 **$15**（每 1M tokens）

| 分组 | 倍率 | ≈官网（÷7） | 约卖价 入/出（每 1M） |
|------|------|-------------|----------------------|
| Kiro（逆向） | 1.1 | ~15.7% | ~$0.47 / $2.36 |
| 官线 | 5.95 | ~85% | ~$2.55 / $12.75 |

**充 $100 →**（按 50 万额度=$1）→ **5,000 万额度**。

一次请求：输入 2,000、输出 800（按有效美元价理解）：

| 分组 | 约费用 |
|------|--------|
| Kiro | ≈ $0.00283 |
| 官线 | ≈ $0.0153 |

同模型同 token，只因分组，贵约 5 倍。

粗算「$100 纯输入能买多少」（忽略输出，只比数量级）：

| 分组 | 约入价 $/1M | $100 大约量级 |
|------|-------------|---------------|
| Kiro | ~$0.47 | ~2.1 亿 tokens |
| 官线 | ~$2.55 | ~3900 万 tokens |

> 注：「逆向」= 非官方便宜通道（号池/非官方桥等），官线=原厂/云正源；便宜与风险、合规相关。Trinity 不宜把逆向当对外主货架。

## 3. 优缺点对比

| 维度 | A 额度 + 倍率 | B 绝对价 |
|------|---------------|----------|
| **改价速度** | ✅ 改系数适合海量模型×多分组 | 改单价表；心智是「价」 |
| **多通道分档** | ✅ 分组倍率天然表达官/逆向 | ✅ 可做标准档/高可用；或对内选路 |
| **客户好懂** | ❌ 额度、倍率、刻度要解释 | ✅ 与官网、账单同口径 |
| **对账 / 财务** | ❌ 点↔钱、倍率变更难审计 | ✅ 与发票、合同、GM 一致 |
| **ToB 商务** | ❌ 合同难写倍率 | ✅ 刊例 + 阶梯折 |
| **官网对照话术** | 靠折扣列翻译 | 直接挂价或「约官网 x 折」 |
| **工程** | ✅ 开源网关开箱 | 自建价目与扣费 |
| **品牌合规** | 易绑特价/逆向分组 | 更易讲正源刊例 |
| **是否支持预付** | ✅ | ✅（Trinity 已是） |

## 4. 市面主流用哪种（按赛道）

| 赛道 | 主流对客/改价表达 | 代表 |
|------|-------------------|------|
| 中文 API 中转/分发 | **A 额度 + 分组倍率** | NewAPI 站、APIhub 类、Nexcor、OpenSand、AIUPNode |
| 国际路由市场 | **B 绝对 $/M** | OpenRouter |
| 开源/推理云 | **B 绝对价** | 硅基、Together、Fireworks 等 |
| 原厂 / 云 MaaS | **B 绝对价**（可合同折） | OpenAI、Anthropic、Azure、Bedrock、百炼 |
| 企业网关管控 | 多为透传或自定绝对价 | Portkey 等 |

**没有唯一全球主流**：中转圈 A 主流；云/原厂/国际聚合/ToB **B 主流**。  
部分中转站对外显示美元，对内仍用倍率改价——**看起来像 B，骨子里是 A**。

## 5. 和「动态计费 / 多线路」的关系

| 概念 | 含义 | 建议（Trinity） |
|------|------|-----------------|
| 交叉多线路 | 同模型多供应线 | ✅ 对内已有 |
| 动态选路 | 客价固定，优先走合格且成本更优主供 | ✅ 推荐 |
| 动态扣费 | 命中哪条线就按哪条线价扣客户 | ⚠️ 账单飘，冲击对外标准价 |
| 竞品「动态计费」 | 常指策略/变体改价 | ≠「按成本折自动改客价」 |

APIhub 表：**只列各分组价，不写混合线路怎么计费**。  
若 Trinity 做自动选路，对外应写清：**对客按标准档（或合同档）扣，与实际命中哪条合格主供无关**（二转仅备线、不因最便宜而最高优先）。

## 6. 对 Trinity 的建议（决策摘要）

| 项 | 建议 |
|----|------|
| 现算哪种 | **B：预充值 + 绝对价**（不是 NewAPI 额度制） |
| 对外报价表 | **绝对价**为主；可选「约官网 x 折」；**不上倍率主列** |
| 商务洽谈表 | 继续对内博弈；不整表外发 |
| 可借鉴 A 的 | 多线路分档思想、分组=通道；**不借鉴**对外卖逆向 + 额度倍率母语 |
| 是否改造成 A | **不建议**为「像中转站」而改；与现有刊例/商务/对账体系冲突大 |
