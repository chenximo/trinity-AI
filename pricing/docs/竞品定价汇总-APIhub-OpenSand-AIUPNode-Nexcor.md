### 1.1 分组语义：两种贴法（对 Trinity 三类）

NewAPI「分组」只是槽位；**贴什么由运营决定**：

| 贴法 | 分组在表达 | 代表 | 与 Trinity 三类 |
|------|------------|------|-----------------|
| **按上游/通道** | 官 Key、云、二转/号池 | **Nexcor**；APIhub 官/逆向 | 对内打标可对齐；对外是否暴露另定 |
| **按客群/折扣** | 企业、折扣 A/B/C | **OpenSand** | 更像商务档，不是供应分类 |
| **套餐/促销 + 充值折** | 普通包月 / 促销 Sale / 1M 等；充值另打折 | **KuaiGouAI** | 双层旋钮；对外不宜照搬 |

Trinity 供应三类（官 Key / 云 MaaS / 二转）见 [OUTWARD-QUOTE-AND-SUPPLY-CLASS.md](./OUTWARD-QUOTE-AND-SUPPLY-CLASS.md)：对内必融；对外建议只融主供标准档，二转不进客户价目。

### 1.2 「抬倍率 + 充值折」双层玩法（KuaiGouAI 典型）

```text
层① 调用侧：标准价锚（常近官价）× 分组倍率 → 抬高/拉开实际扣额度
层② 付款侧：按充值金额给 7～8.8 折 → 营销「充越多越便宜」
客户体感：「打了 7 折」；底座可能已被倍率抬过，最终不一定真低于官价。
```

粗算（Claude 输出标准列 `$25/1M`，充值折取 **7～8.8 折**）：

| 分组 | 分组倍率 | 抬价后约 | × 充值折后约 | 相对官价锚 `$25` |
|------|----------|----------|--------------|------------------|
| Claude 促销 | **1.2×** | ≈ $30 | ≈ **$21～$26** | 可能略低或接近 |
| 普通包月 | **1.8×** | ≈ $45 | ≈ **$31～$40** | 仍明显高于官价 |
| 1M 上下文 | **3.0×** | ≈ $75 | ≈ **$52～$66** | 贵很多 |

→ 详例与证据见 **§8 KuaiGouAI**。  
→ Trinity：**不要**对外学这套话术；继续 **目录绝对价 + 预充值达档真实降单价**。

## 3. NewAPI 计费母语（读 OpenSand / AIUPNode / Nexcor / KuaiGouAI 前先读）


### 3.1 按量（Token-based）

```text
额度 ≈ (输入 tokens + 输出 tokens × 补全倍率) × 模型倍率 × 分组倍率
```

页面常标「按量计费」。接口字段多为 `quota_type=0` + `model_ratio` + `completion_ratio`。

### 3.2 按次（Per Request / Fixed price）

```text
每次请求扣固定价 model_price（再视站点是否乘分组）
```

页面常标「按次计费」。接口多为 `quota_type=1`，`model_ratio=0`。

### 3.3 动态（Dynamic Pricing）

通常**不是**第三种互斥单位，而是：

- 定价策略（如「默认折扣…」）随官方锚调整；和/或  
- 同一模型多 **variant**（分辨率、是否参考图等）→ 不同有效价。

底层仍落在「按量」或「按次」之一。

### 3.4 阅读注意

站点前端会把倍率**换算成 $/¥·M 展示**；公开 API 有时只给倍率。下文 OpenSand 样例以接口字段为准，不把换算美元写成官方承诺。

### ③ 价格怎么算

**海外按量：**

```text
相对官网折扣 ≈ 倍率 ÷ 7     （该表私有刻度，非行业标准）
卖价 ≈ 官网价 × (倍率 ÷ 7)
```

模型行常写「按分组确定倍率」：先查该模型所属家族的分组倍率表，再套官网（或「1 倍率标准」列）。

**海外按次：** 表直接给「按次计费」美元；折扣列仍常见 ≈ 倍率÷7。

**国内按量：**

```text
折扣 = 卖价 ÷ 官网价（CNY / 1M tokens 等）
```

- 折扣组：`enable_groups` 含 `discount-A/B/C` 的模型，**账号进对应组后**才按该组倍率；公开默认组展示偏企业基准。

### ② 计费类型怎么划分

| 对方说法 | 我们的解释 |
|----------|------------|
| 按量 / token 透明计费 | NewAPI **按量倍率**路径；页面展示「标准 $/1M」+「分组倍率」 |
| 按量充值折扣 | **付款侧**人民币买额度优惠（与调用倍率分离） |
| 包月套餐 | 固定月费换定额/周期额度（changelog 有每周到账等规则）；与按量并行 |

### ③ 价格怎么算（双层）

```text
层① 调用扣额度 ≈ f(标准价锚, 分组倍率, tokens…)
     表上读法：体感单价 ≈ 标准入/出 × 分组倍率
     （倍率越高越贵：1.2× 促销 < 1.8× 普通包月 < 3.0× 1M）

层② 充值实付 = 面额 × 充值折扣
     ¥10 起 8.8 折 · ¥100 起 8 折 · ¥500 起 7 折
     （见定价页）

有效人民币成本 ≈ 层①消耗 ÷ 层②充值兑换优惠
```

**对外话术陷阱**：客户只看到「7 折充值」，不一定核对分组倍率是否已抬底座。

### ④ 分组 / 档位（Claude 页公开）

来源：[Anthropic Claude 系列](https://api.askmind.cn/share/models/anthropic)

| 分组 | 分组倍率 | 备注 |
|------|----------|------|
| Claude 促销 Sale | **1.2×** | 促销模型 ID 常带 `-sale` |
| 普通包月 Monthly | **1.8×** | |
| Claude 包月旗舰 / 全能包月旗舰 | **2.0×** | |
| Claude 1M 上下文 | **3.0×** | 长上下文更贵 |

标准列示例（近官价锚）：Opus 入 `$5` / 出 `$25`；Sonnet 入 `$3` / 出 `$15`。

充值档（定价页）：

| 充值金额 | 折扣 |

### ⑤ 样例价（抬倍率 + 充值折 · 粗算）

假设输出标准列 **`$25/1M`**，充值折取 **7～8.8 折**（与首页「7 折起」一致）：

| 分组 | 倍率 | 抬价后约 | ×7～8.8 折后约 | 相对官价锚 |
|------|------|----------|----------------|------------|
| 促销 | 1.2× | ≈ $30 | ≈ **$21～$26** | 可能略低或接近 |
| 普通包月 | 1.8× | ≈ $45 | ≈ **$31～$40** | 仍明显高于官价 |
| 1M | 3.0× | ≈ $75 | ≈ **$52～$66** | 贵很多 |

页脚自述：价格仅市场参考，**以控制台与实际调用为准**。
