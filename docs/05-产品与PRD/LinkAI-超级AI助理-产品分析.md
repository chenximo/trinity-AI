## 一、执行摘要

**LinkAI 超级 AI 助理**是深圳极简未来科技旗下 LinkAI 平台推出的 **新一代 Agent 产品**，定位是「能自主规划、操作计算机、执行技能、积累记忆并持续成长的专属 AI 助理」。

与「只卖模型 API」的聚合平台不同，LinkAI 走的是 **垂直整合路线**：

- **底层**：多模型 MaaS（100+ 模型）
- **中间层**：Agent Harness（规划、工具、记忆、知识、技能）
- **上层**：渠道接入（微信 / 飞书 / 钉钉等）+ 开箱产品体验

商业上采用 **开源 CowAgent 获客 + LinkAI 云端/桌面托管变现 + 企业版/私有化 upsell** 的组合。GitHub 约 46k star 带来开发者认知；产品页强调「3 分钟创建、7×24 在线、1 万+ 技能」，面向 **个人效率、小团队 IM 机器人、轻量数字员工** 为主；政企大单则走 **企业智能体平台 + 私有化** 另一条产品线。

**一句话判断**：这是当前国内较完整的 **「Super Agent / Agent Harness 产品化」** 样本——强在 **体验闭环与 IM 渠道**，弱在 **政企级治理叙事需另看企业版**；与纯 API 聚合平台是 **竞合关系** 而非简单替代。

## 二、公司与产品矩阵

### 2.1 主体

| 项 | 说明 |
|----|------|
| **公司** | 深圳极简未来科技 |
| **品牌** | LinkAI — 对外称「一站式 AI 智能体平台」 |

### 2.2 LinkAI 产品线（SuperAgent 在其中的位置）

| 产品 | 定位 | 与 SuperAgent 关系 |
|------|------|-------------------|
| **超级 AI 助理（SuperAgent）** | 开箱即用的个人/团队超级 Agent | **本文主角** |
| **智能体搭建平台（Builder）** | 零代码搭 Agent、接渠道 | 能力可「安装为技能」挂到 SuperAgent |
| **内容创作平台（Studio）** | 内容生产 | 场景向，可与 Agent 组合 |
| **模型服务（MaaS）** | 多模态模型 API / 积分计费 | SuperAgent 的「大脑」来源 |
| **企业智能体平台** | 客服、培训、知识问答、数据分析、系统集成 | 企业级；含私有化 + 多智能体协同 |

SuperAgent 不是孤立 SKU，而是 **LinkAI 能力栈的消费端入口**：平台上的应用、知识库、数据库、工作流都可 **安装为 SuperAgent 的技能**，形成「一个助理 + 平台资源插件化」的架构。

```text
        ↓ 商业化 / 托管
LinkAI 平台
├─ 超级 AI 助理（云端托管 / 桌面客户端）
```

## 三、产品定义与目标用户

### 3.1 产品定义

**官方定义**（[产品文档](https://docs.link-ai.tech/platform/product/personal-assistant)）：自主思考规划、操作计算机与外部资源、创造和执行 Skills、长期记忆并成长，通过 Skills 集成知识库与业务系统，落地 **个人助手或数字员工**。

**技术本质**：基于 CowAgent 的 **Agent Harness** —— 消息从 Channel 进入，Agent Core 结合 Memory / Knowledge / Tools / Skills 做规划与决策，调用 Model 生成结果，再经原 Channel 返回。

### 3.2 目标用户分层

| 层级 | 用户 | 典型诉求 | 推荐形态 |
|------|------|----------|----------|
| **C 端 / 个人** | 创作者、开发者、知识工作者 | 写作、Coding、本地文件、知识沉淀 | 桌面客户端 或 云端 |
| **小团队** | 运营、销售、工作室 | 微信/飞书机器人、定时任务、内容批量生产 | 云端托管 |
| **成长型企业** | 无专职 AI 团队的业务部门 | 快速上线 IM 助手、接平台知识库 | 标准版/专业版 + SuperAgent |
| **中大型企业** | IT + 业务部门 | 合规、私有化、与 OA/ERP 打通 | **企业智能体平台**（非仅 SuperAgent 消费页） |

产品页场景（内容运营、行情分析、Vibe Coding、企业提效）覆盖 **生成型 + 工具型 + 轻度办事型** 需求；**不是**典型「政企 OA 内嵌、密级分区、审计验收」的一期方案，后者需企业产品线补齐。

```text
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐

│  ┌──────────────┐    ┌──────────────────────────────────┐   │
│  │ Tools (10+)  │    │ Skills（Hub/GitHub/NL 创建/平台资源）│   │

│  └──────────────┘                                            │
└───────────────────────────┬─────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  Models：OpenAI · Claude · Gemini · DeepSeek · Qwen · GLM …  │
└─────────────────────────────────────────────────────────────┘
```

CowAgent 自述：完整的 **Agent Harness** —— 各模块解耦，按需扩展。详见 [CowAgent 项目架构](https://docs.cowagent.ai/zh/intro/architecture)。

### 4.2 CowAgent 核心模块一览

| 模块 | 说明 |
|------|------|
| **Plan** | 理解意图，分解多步计划，循环调工具直到完成目标 |
| **Memory** | 核心记忆 + 天级记忆；关键词与向量混合检索 |
| **Knowledge** | Agent 自主整理 Markdown Wiki，索引与交叉引用，知识图谱 |
| **Evolution** | 对话空闲后隔离环境复盘，优化技能、补记忆与知识 |
| **Tools** | 文件、终端、浏览器、定时、记忆检索、联网搜索等 10+ 种 |
| **Skills** | Skill Hub、GitHub、对话创建；LinkAI 平台资源可装为技能 |
| **Models** | 统一接入国内外主流 LLM |
| **Channels** | Web、微信、飞书、钉钉、企微、公众号等，统一消息协议 |
| **CLI** | `cow` 命令与 `/` 对话命令，管理进程、技能、配置 |

### 4.3 Agent 运行时工作流

> **图类型**：流程图（Flowchart）

```text
1. 接收消息（Channel）
        ↓
2. 理解意图（Memory / Knowledge 上下文）
        ↓
3. 规划任务（Plan · 多步分解）
        ↓
4. 调用工具 / 技能（循环直至完成或触顶）
        ↓
5. 更新记忆与知识（持久化）
        ↓
6. 返回结果（原 Channel · 支持多模态）
```

这是典型的 **ReAct / Agent Loop** 产品化实现，而非固定 DAG Workflow。对照内部文档：[§4.2 执行层三档](./大模型训练三阶段与聚合平台定位.md#42-执行层把岗位流程封成-agent)、[§5.13 Agentic Workflow 专节](./大模型训练三阶段与聚合平台定位.md#513-agentic-workflow-专节对比总结)。

### 4.4 工作空间与隔离

**系统工作空间**（默认 `~/cow`）：

```text
~/cow/
├── SYSTEM.md          # Agent system prompt
├── USER.md            # User profile
├── MEMORY.md          # Core memory
├── memory/            # Long-term memory storage
│   └── YYYY-MM-DD.md  # Daily memory
├── knowledge/         # Personal knowledge base
│   ├── index.md
│   └── <category>/
└── skills/
    ├── skill-1/
    └── skill-2/
```

秘钥单独存放于 `~/.cow/.env`。

**项目工作空间**：会话可绑定独立项目目录，文件读写在该目录内进行；记忆/技能仍全局共享。Web/桌面端按项目分组历史会话。

**权限三档**（CowAgent 配置项）：

| 模式 | 说明 |
|------|------|
| `read-only` | 只读 |
| `workspace-write` | 工作区可写 |
| `full-access` | 全部可访问（开源默认） |

另有 **会话级模型切换**、**全局/会话级权限**，用于控制成本与误操作风险；文档建议强隔离场景在容器中运行。

### 4.5 关键控制参数（成本与行为边界）

| 参数 | 含义 | 典型默认值 |
|------|------|-----------|
| `agent_max_steps` | 单次任务最大决策步数 | 15～20 |
| `agent_max_context_turns` | 最大记忆轮次 | 20～30 |
| `agent_max_context_tokens` | 上下文 Token 上限 | 4～5 万 |
| `self_evolution_enabled` | 是否启用自主进化 | 开源默认 `false` |

LinkAI 控制台对 **最大执行步数、记忆轮次、上下文长度** 提供可视化调节，面向 **算力成本控制** —— 开放 Loop 产品的必备产品化能力。

## 五、核心能力深度解析

### 5.1 复杂任务规划（Plan + Tools）

**能力**：理解复杂目标 → 自主分解 → 持续调用工具直至完成或触顶。

**内置工具**（[任务规划与工具调用](https://docs.link-ai.tech/platform/superagent/features/tools)）：

| 类别 | 能力 |
|------|------|
| **终端与文件** | 读写编辑、Bash、文件发送 |
| **浏览器** | 导航、点击、填表、快照、截图、JavaScript |
| **定时任务** | 一次性 / 固定间隔 / Cron；固定消息或 Agent 动态执行 |
| **其他** | 记忆搜索、联网搜索、环境配置等 |

**PM 注意**：

- 云端托管操作 **LinkAI 分配的云电脑**，不是用户本机。
- 桌面客户端操作 **本机** 资源；对话内容仍经 LinkAI 模型服务。
- 定时任务：云端 7×24；桌面依赖开机在线。

**归类**（内部框架）：开放 **Single-Agent Loop** + 操作系统级 Tool Use，接近 Claude Code / Devin 能力谱，但包装成「人人可用的助理」。

### 5.2 长期记忆（Memory）

**结构**：

- **上下文记忆** — 当前会话
- **天级记忆** — 按日 Markdown 文件
- **核心记忆** — 长期稳定事实（MEMORY.md）

**检索**：关键词 + 向量 **混合检索**。  
**「梦境蒸馏」**：空闲时自动整理天级 → 核心记忆（与 Evolution 联动）。

**产品差异**：多数「Chat + RAG」无跨会话人格记忆；SuperAgent 把 Memory **文件化、可可视化、可回溯**，支撑「越用越懂你」叙事。

### 5.3 知识库（Knowledge）

**不仅是**静态「上传 PDF 做 RAG」：

- Agent **自主整理**有价值信息为 Markdown 页面
- 维护 index、交叉引用、**知识图谱可视化**
- 支持目录树浏览、本地导入、链接/笔记一键沉淀

定位更接近 **「会生长的个人/团队 Wiki」**，由 Agent 维护。

与 LinkAI 平台企业知识库：平台 KB 可 **安装为 Skill**；SuperAgent 既可自建 Knowledge，也可 **外挂平台 KB**。

### 5.4 技能系统（Skills）

**来源**：

- 预置常用技能
- Skill Hub / GitHub 一键安装（宣传 10,000+）
- **自然语言对话创建**自定义 Skill
- LinkAI **应用 / 知识库 / 数据库 / 工作流** 安装为技能

**生态意义**：Skills 是 **集成层** —— 把 Builder 搭的低代码 Agent、平台 DB、工作流封装成 SuperAgent 可调用的能力包。语义上对齐 Agent 圈的 **Skill**（内部文档 [§五 Skill](./大模型训练三阶段与聚合平台定位.md#五rag--agent--skill--mcp概念关联与选型)），非 MCP 主打。

### 5.5 自主进化（Evolution）

对话空闲后在 **隔离环境** 自动复盘：

- 优化技能
- 处理遗留待办
- 补全记忆与知识

开源默认 `self_evolution_enabled: false`，说明团队亦知 **生产环境自动改行为** 的风险。对产品是差异化卖点；对政企须问 **变更审计、回滚、人工审批**（对照 [§4.7 安全护栏](./大模型训练三阶段与聚合平台定位.md#47-安全护栏-guardrails-pm-专节) **④ 行动护栏 + HITL**）。

### 5.6 多模型接入

支持 OpenAI、Claude、Gemini、DeepSeek、MiniMax、GLM、Qwen、Kimi、Doubao 等；与 LinkAI MaaS 积分体系打通。

产品逻辑：**Harness 稳定，大脑可换** —— 与内部「Harness ≠ Model」一致。

### 5.7 多端部署（Channels）

一个 Agent 实例可同时接 **10+ 渠道**，多模态消息（文本/图/语音/文件）。

CowAgent  heritage：**中国 IM 生态**（微信、企微、飞书、钉钉）是核心壁垒之一。

## 六、两种使用方式

| 维度 | 云端托管 ☁️ | 桌面客户端 💻 |
|------|------------|--------------|
| **价值主张** | 免安装、约 3 分钟创建、7×24 | 本机文件/终端/浏览器直连 |
| **运行环境** | LinkAI 独立云电脑 | 用户 macOS / Windows |
| **工作空间** | 云端独立空间 | 本机目录（可本地 KB 不上云） |
| **定时任务** | 持续在线 | 依赖本机开机 |
| **渠道** | 微信/飞书等，配置一致 | 同左；手机可远程触发本机任务 |
| **平台资源** | 应用/KB/DB/工作流可装为技能 | 同左 |
| **成本结构** | 云电脑 + 模型积分 |  mainly 模型积分 |
| **典型场景** | IM 机器人、行情监控、云端内容流水线 | Vibe Coding、本地文档批处理 |
| **账号** | 同一 LinkAI 账号与积分，可同时使用 | 同左 |

**产品设计亮点**：**同一 Agent 能力、两种 Runtime** —— 不强迫「数据必须上云」，同时保留云端订阅与桌面引流。

### 6.1 如何选择（决策树）

> **图类型**：决策树

```text
问：主要操作对象在哪里？任务要不要 7×24？
├─ 要 IM 机器人 / 定时任务 / 不想装软件
│   └─ → 云端托管（操作云电脑内资源）
│
└─ 要改本机文档/代码/终端 · 敏感文件不愿上传
    └─ → 桌面客户端（操作本机资源；模型调用仍走 LinkAI）
```

## 七、典型场景与能力匹配

| 场景 | 用户行为 | 主要能力组合 | 匹配度 |
|------|----------|-------------|--------|
| **内容运营** | 飞书对话生成文案/图/视频，迭代修改 | Channel + Agent + 创作类 Skill | ⭐⭐⭐⭐⭐ |
| **行情分析** | 监控资讯、整合解读 | 搜索 Tool + Memory + 定时任务 | ⭐⭐⭐⭐ |
| **Vibe Coding** | 需求→UI→代码→GitHub→部署 | 终端 + 浏览器 + GitHub Skill；桌面更佳 | ⭐⭐⭐⭐⭐ |
| **企业提效** | 读平台 KB/DB 写报告 | Skills 接平台资源 + Agent | ⭐⭐⭐⭐ |
| **本地文件处理** | 批量整理 Excel/PDF | 桌面 + 文件 Tool | ⭐⭐⭐⭐⭐ |
| **本地知识沉淀** | 丢链接/笔记 → 结构化 KB | Knowledge + Evolution | ⭐⭐⭐⭐ |
| **政企制度问答** | 密级、引用、条线隔离 | 需平台 KB + 企业版治理；开放 Loop 非首选 | ⭐⭐⭐ |
| **固定 SOP 批量报表** | 每月固定出表 | Workflow 更合适；SuperAgent 可能 overkill | ⭐⭐ |

### 7.1 与内部「四场景」框架对照

对照 [§5.7.2.1 首问四分类](./大模型训练三阶段与聚合平台定位.md)：

| 内部场景类型 | LinkAI 官方场景 | 说明 |
|-------------|----------------|------|
| **只答** | 本地知识沉淀（部分） | 更偏「会写的 KB」，非纯 citation 问答 |
| **答 + 生成** | 内容运营 | 高度匹配 |
| **办事** | Vibe Coding、企业提效 | 工具+Skill 办事；非典型 OA 审批链 |
| **固定流程** | 定时任务 | 有 Cron，但主叙事是 Agent 非 Workflow |

## 八、商业模式与定价

### 8.1 收入结构

1. **版本订阅** — 基础（免费体验）/ 标准 / 专业 / 企业
2. **模型积分** — 按量消耗（[计费规则](https://docs.link-ai.tech/platform/funds/price)）
3. **插件/技能调用** — 部分按执行次数
4. **企业定制** — 私有化部署、容量定制、顾问服务

### 8.2 版本与参考价格

> 以下为第三方渠道（如百度千帆应用商店）公示参考价，**实际以 LinkAI 官网为准**。

| 版本 | 参考价 | 适合 |
|------|--------|------|
| 基础版 | 体验级（赠积分） | 试用 |
| 标准版 | 约 ¥298/月 或 ¥2980/年 | 个人/小团队 |
| 专业版 | 约 ¥7980/年 | 成长型企业 |
| 企业版 | 约 ¥19800/年起 | 中大型；可 SaaS/私有化 |

**积分**：约 1 积分 = 0.0016～0.0019 元（随套餐浮动）；各模型实时价见平台模型服务页。

SuperAgent 云端托管隐含 **云电脑资源**；步数/上下文调大后 **积分消耗不可预测** —— 开放 Loop 产品通病。

### 8.3 开源 vs 商业

| | CowAgent 开源 | LinkAI 商业 |
|--|--------------|-------------|
| 部署 | 自托管、可改源码 | 托管 / 桌面 / 私有化 |
| 模型 | 自配 API Key | 平台 MaaS 积分 |
| 渠道 | 自行配置 | 控制台一键 |
| 企业功能 | 社区/自建 | 权限、审计、顾问、私有化 |
| 商业逻辑 | Star + 导流到 LinkAI | 订阅 + 积分 + 企业项目 |

### 8.4 企业线补充

[企业智能体平台](https://docs.link-ai.tech/platform/product/digital-employee) 提供：

- 知识库、数据库、工作流、**多智能体协同**、插件系统
- 端到端交付（知识库搭建、提示词、渠道接入、培训）
- **私有化部署**（LinkAI 基础平台 + 超级 Agent 助理），数据自主可控
- 可本地部署 DeepSeek 等开源模型（私有化方案宣传）

政企大单应 **以企业产品线为准**，SuperAgent 消费页不能代表全部交付能力。

## 九、竞争格局

### 9.1 同类 / 相邻产品

| 类型 | 代表 | 与 LinkAI SuperAgent 差异 |
|------|------|---------------------------|
| **IM 机器人 / 低代码 Agent** | Dify、Coze（扣子）、FastGPT | LinkAI 更强调 **OS 级 Tool + Memory + 自进化** |
| **Coding Agent** | Cursor、Claude Code、Devin | LinkAI 场景更广；Coding 深度可能不及专用 IDE Agent |
| **个人 AI OS / Desktop Agent** | 各类 Desktop Agent 开源项目 | LinkAI 有 **云端 7×24 + 中国 IM** |
| **模型 API 聚合** | 各类 MaaS 网关 | LinkAI **自己也做 MaaS**，SuperAgent 卖 Harness 产品 |
| **企业 Agent 平台** | 火山 HiAgent、百度千帆、阿里百炼 Agent | LinkAI 轻量上线快；大单拼私有化 + 集成 |

### 9.2 差异化总结

**最强差异**：

1. CowAgent 开源社区 + ~46k star 信任背书
2. **微信 / 飞书 / 钉钉** 原生多渠道
3. **云端 + 桌面双 Runtime** 同一产品
4. **Skills 万级生态** + 平台资源插件化
5. **Memory / Knowledge 文件化、可成长** 完整叙事

**相对薄弱**：

1. 政企 **密级/条线/验收指标** 在 SuperAgent 消费页不突出
2. **开放 Loop 成本与稳定性** 企业 CFO 敏感
3. **Evolution 自动改技能** 生产可控性待验证
4. 与重型 OA/KMS 深度集成靠 Skill/顾问，非标准企业中间件故事

## 十、优势、风险与适用边界

### 10.1 优势

| 维度 | 说明 |
|------|------|
| **完整度** | Plan + Tool + Memory + Knowledge + Skill + Channel 闭环，个人/小团队 TTM 极短 |
| **体验** | 「3 分钟创建」「边聊边改」「越用越聪明」降低 Agent 认知门槛 |
| **渠道** | 中国办公 IM 全覆盖，私域运营/内部助手落地快 |
| **灵活性** | 多模型、多 Runtime、开源可私有化 |
| **平台协同** | SuperAgent 消费 Builder/KB/DB/工作流，LTV 可扩展 |

### 10.2 风险与局限

| 风险 | 详情 |
|------|------|
| **权限过大** | 终端/浏览器/写文件 → 误删、越权、注入后执行恶意命令 |
| **成本波动** | 多步 Loop + 长上下文 + 云电脑 → 账单难预估 |
| **数据合规** | 云端托管数据在 LinkAI 环境；金融/政务需私有化或桌面 |
| **预期管理** | 「超级」「什么都能干」易引发万能 Agent 幻想 |
| **进化不可控** | Evolution 改 Skill/Memory 需版本管理与审计 |
| **企业深度** | 复杂审批链、HITL、ROI 归因需企业版 + 定制 |

### 10.3 适用边界（决策树）

> **图类型**：决策树 —— 可与 [内部 §5.7.2.1](./大模型训练三阶段与聚合平台定位.md) 对照使用。

```text
问：你的核心诉求是什么？
├─ IM 里有个能干活的小助手 · 内容/Coding/本地文件
│   └─ → ✅ SuperAgent 高度匹配（选云或桌面）
│
├─ 只答制度 · 强 citation · 密级 RBAC · 采购硬指标
│   └─ → ⚠️ 传统 RAG + 治理优先；SuperAgent 开放 Loop 非首选
│
├─ 固定 SOP 批量报表 · 路径几乎不变
│   └─ → ⚠️ Workflow / Agentic Workflow 更合适
│
├─ 多角色必须同时协作审同一对象
│   └─ → ⚠️ Multi-Agent 或人工流程；先拆「多场景 vs 多角色」（§5.15.5）
│
└─ 数据不能出域 / 必须本地模型
    └─ → LinkAI 企业版私有化 或 CowAgent 自部署 + 自建模型
```

## 十一、与 API 聚合平台的关系

以 [AI-API聚合平台-产品全景与介绍](./AI-API聚合平台-产品全景与介绍.md) 所描述的 **API 聚合平台** 为参照：

| 维度 | API 聚合平台 | LinkAI SuperAgent |
|------|-------------|-------------------|
| **卖什么** | 模型接入、计量、密钥、路由、API 侧治理 | **完整 Agent 体验** + 渠道 + 技能 |
| **客户建什么** | 自建 RAG/Agent/门户/治理 | 主要配 Skill、选模型、接渠道 |
| **价值锚点** | 多模型、成本可见、企业 API 治理 | 开箱数字员工、IM 触达、Harness |
| **是否炼模型** | 否 | 否（用 MaaS；私有化可本地部署开源模型） |
| **关系** | 可 **竞合** | 部分客户「全家桶 LinkAI」vs「聚合 API + 自研 Agent」 |

**不替代、可互补**：

- 聚合平台客户可把 LinkAI/CowAgent 当作 **下游应用形态参考** 或 **轻量 Agent 备选**。
- 若平台只做 API 线，SuperAgent 在 **C 端/轻量 B 端助理** 赛道不构成直接 SKU 竞争，但在售前「企业要不要自研 Agent」对话中会被对比。

**内部对照句**：

> LinkAI 超级 AI 助理 ≈ 开源 CowAgent 的商业托管版，定位 **开箱即用 Super Agent + 渠道 + 技能市场**；政企全案仍要单独设计治理与分期（参见 [§十二 实战案例](./大模型训练三阶段与聚合平台定位.md#十二实战案例政企统一-ai-门户完整需求--mvp1-方案练手)）。

## 十二、总结判断

LinkAI 超级 AI 助理是 **CowAgent 开源 Harness 的商业化旗舰 SKU**，代表国内 **「Agent 从 Demo 到可订阅产品」** 的一条成熟路径：用 Memory + Knowledge + Skills + IM 渠道建立粘性，用云端/桌面双 Runtime 覆盖不同数据敏感度，用平台插件化把 Builder、KB、工作流收进一个助理入口。

### PM 应重点看的四点

1. **Harness 与 Model 分离** — 换模型不换技能/记忆/渠道（与内部「Harness ≠ Model」一致）
2. **步数 / 上下文 / 权限三旋钮** — 控成本与风险的标配产品化
3. **Skills 生态 > 纯 Prompt** — 集成层替代部分 MCP/定制开发
4. **开源 + 托管 + 私有化三级漏斗** — 从社区到企业单的商业路径
