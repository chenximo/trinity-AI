## P03 行业与竞品 · 1:30

（翻到 P03）

先说为什么做聚合。大模型厂商接口、计费、限流各不相同，客户多头接入成本高，**统一网关加路由加计费**是刚需。我们不做训练、不做自研模型，做的是**路由层和商业化层**。

对客我们坚持**预充值加绝对价**，不做国内中转站常见的「额度乘倍率」主叙事。差异化不只是堆模型，而是把**管价、审价、报价、对账**产品化。

竞品上，**OpenRouter** 开发者心智很强，和我们同属绝对价阵营；我们补强的是**企业商务路径**——**对外报价稿 L3a、对内商务底座 L3b**——以及**定价运营闭环**：价审一点按钮、人确认写价、对账分柱。不是「再做一个聚合」。

另外我们和额度倍率类中转站的差别，在于绝对价加 Credits；和绝对价同行的差别，在于补齐**对外报价稿 L3a、对内商务底座 L3b** 和价审写回整套运营能力。

## P04 关键决策复盘 · 2:00

（翻到 P04）

这一页是总：我在商业化上做了两个维度的决策。

**维度 A，商业化定价规则**——刊例、累积消耗档、折扣，定什么价、怎么卖。  
**维度 B，运营工程化**——重复审价运维怎么进系统、怎么可重复跑。

A 维度我重点讲三条：  
**A1**，选**预充值加绝对价**。我们讨论过订阅、也讨论过倍率，最终开发者要的是「调这个模型到底多少钱」，所以选绝对价，商务深折走**对内商务底座 L3b**。  
**A2**，**刊例 L2 加累积消耗档加折扣**，对外三档、对内更深，达档给折走商务合同，不自动改运行时单价。  
**A3**，**对外报价稿 L3a 可外发、对内商务底座 L3b 内用**；官网只浅折、场景和找商务，成本和 GM 不上官网。

B 维度：  
**B1**，**人确认写价**，写回本轮只上浮不降，不做静默改价。  
**B2**，**价审出包工程化**，一点按钮出确认单，替代长期人肉跑脚本传文件。  
**B3**，**对账与跟价分柱**，成本核对和「要不要改刊例」分开，不混成一笔账。

范围上：**API 主线、云辅线、GEO 降权**；接入坚持 **OpenAI 兼容**。对客是稳定标价，对内是多线路选路，不把二转说明书摊给客户。

## P05 定价系统 · 2:30

（翻到 P05，本页最重）

第 5 页展开维度 B，讲**定价系统**——内部怎么定、审、写、对。

价格分四层：**L0** 官方锚，**L1** 进货挂牌，**L2** 线上基础刊例——这是人确认写回后的**扣费真源**；**L3a 是对外报价稿，L3b 是对内商务底座**，都由规则加 L2 **派生**出来，卖法在第 6 页讲。

闭环是：  
官方和上游价进来 → 测算固化定折规则 → **刊例价审**：一点按钮出确认单 → **人确认写价到 L2** → 系统派生**对外报价稿 L3a**和**对内商务底座 L3b** → 月对账，平台成本 Token 对上游实付，**和跟价改刊例分柱并行**。

测算不是一次性 Excel：输入成本折族和约束，各档折扣乘 GM 护栏，对内五档对外三档多版对比，固化成**可复用定价规则**，改矩阵须确认再生，写回后检 GM。

价审运营上，以前我自己跑脚本、传文件、对任务；现在是**一点按钮大约三分钟出确认单**，我只做人确认写价。出包环节自动化大约 **95%**——请注意，**95% 仅指出包和确认单，不含确认写价**；省的是 PM 在三人团队里 otherwise 会被重复劳动淹死的时间。

（如有录屏可演示：触发价审 → 出确认单）

对账一句：成本核对不等于跟价决策，样例核对我们做过，机制是分柱的。

**本页不讲**官网怎么卖、销售话术——那些在第 6 页。

## P06 商业化策略 · 1:45

（翻到 P06）

第 6 页展开维度 A，讲**商业化**——怎么扣费、怎么护利、销售拿什么出去卖。

**L3a 锁定口径**（也就是对外报价稿，三页统一，只讲这一种）：  
**L3a 对外报价稿与对外三档已就绪，待商务复核后正式发销售；话术同步统一。**  
若现场已外发，您听到的是「已发销售，进入话术与转化验证」——以商务最新状态为准。

计费：**预充值 Credits 加模型绝对价**，用量按 L2 刊例扣，不做倍率主叙事。  
盈利：两块差——成本对对客零售价，以及预充值粘性和档位折如何护 **GM**；对外**报价稿 L3a**只给绝对价，成本不上客表，深折空间在**对内商务底座 L3b**。  
销售套件：官网 Pricing 预付费叙事，**L3a 三档绝对价表**给销售外发，**L3b 商务折扣总册**给商务谈深折，Docs、Cookbook、**开发者 Skill** 降低 POC 成本，brand-deck 和展会物料支撑线下介绍。

一句话：**第 5 页是定价系统，第 6 页是商业化**——系统管价，本页管怎么卖、怎么算。

## P07 开发者与商用门面 · 1:30

（翻到 P07）

主线第二条：**能接、敢买、讲得清**，不只 Docs。

用户路径：快速入门 → API 和多模态 → Cookbook 接到 IDE → **IDE 内 Skill** → Pricing 和充值 → Legal。

文档站 doc.trinitydesk.ai 已对外，不是内部 md。Cookbook 覆盖 Cursor、CodeBuddy 等真实 IDE。  
**开发者 Skill** 在 trinity-skills 仓库，开发者可以在 Cursor 里安装，查模型、配网关、走安全密钥规范——这是**文档之外的产品化接入**。  
合规有 Privacy、Terms、AUP 和商户审核材料；企业路径在 Docs 里写清控制台办事顺序。

产品判断：商务深折不上官网；官网浅折、场景、找商务。  
被问到 Skill 时要分清：**对内协作 Skill** 是团队手册和验收用，**对外开发者 Skill** 是给客户装的——不是同一套。

## P10 未来产品规划 · 能力栈 · 2:00

（翻到 P10）

转正后产品怎么长：从已有**模型平台**向上，**薄封装**，场景少而硬，拉动云一体。

原则三条：接入端先于中台；规范与 Skill 是产品；SaaS 和私有化双路径、同一套管控。

顺序很重要：**先 Agent SDK** 接到 IDE、CLI、OpenAI 兼容接口——SDK 是对外交付面；再薄做 **Agent 智能平台**当孵化器，WorkSession、HITL、评测集，先服务运营与交付，定价、对账、GEO 等 Agent 在平台孵化，稳定后外溢。

中期场景少而硬，**重点是企业 Agent 知识库**：文档入库、切块、向量检索，RAG 接入 Agent 和 OpenAI 兼容 API，按工作区隔离；配合企业私有化交付（子密钥、配额、管控复制），拉动 API 与云用量。我们不做专属算力线路。  
明确不做：研效五 Agent 矩阵、通用工作流编排 SaaS、自研 Agent 内核。

底座是已有的模型平台加云一体，API、云、GEO 三线共享。

## P11 GEO 产品架构 · 1:45

（翻到 P11）

GEO 是第三产品线，**降权但非从零**——文档和控制台原型已通，不进 API 主线排期。本页只讲 GEO **自身架构**。

GEO 是生成式引擎优化：帮助品牌在 ChatGPT、豆包等 AI 答案里讲清**有没有进答案**，并完成诊断、优化、验证闭环。

六环：**策略**定义监测范围；**采集**向十平台提问并归档；**测量**算 SOA 答案份额和 CCR 引用率，**规则计分，不用 LLM 打分**；**诊断** D1 到 D5 加 S1 到 S6 信源缺口；**优化**待办绑定诊断和对标 URL；**验证** R2 复测，先验收信源覆盖再看 SOA。

Trinity 自身是样本：豆包问 API 聚合选型，**SOA 为零**，十六条参考链接里我方为零，归因 S1 S2 S3——说明要有信源盘，不能只看正文。

AI 接在后半段：P1 LLM 解读和草稿；P2 Agent 多步发文和验证编排。挂 Trinity Agent 平台和模型接口，**GEO 不自研 Agent 内核**，Agent 不能改诊断标签。
