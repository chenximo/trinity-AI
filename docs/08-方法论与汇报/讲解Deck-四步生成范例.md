# 讲解 Deck · 四步生成范例

> **文档类型**：方法论文档（给人读、给 AI 按范例生成；**不是 Skill**）  
> **适用**：讲解型 PPT——述职、品牌产品介绍、上架讲解、对外路演  
> **不适用**：SOP、Excel/价表、API 文档、产品手册叶子页  
> **日期**：2026-08-26  
> **落地样例**：转正述职（完整三栏定稿）· 品牌产品介绍 Deck（页上 + 销售备注）  
> **工具**：文字侧 **WorkBuddy**（大纲、定稿更强）· 排版侧 **Cursor**（HTML / 导出）

---

## 0. 一句话

任意讲解 Deck：**先有初版文字（这套 PPT 讲什么、用来做什么）→ WorkBuddy 写大纲并交叉定稿 → Cursor 灌 16:9 HTML → 需要再导出**。改字永远改定稿再灌 HTML，不改 pptx / pdf。

文字方面 **WorkBuddy 比 Cursor 强**：大纲、上屏措辞、口述、口径交叉，优先交给 WorkBuddy；Cursor 最后用来把冻结的定稿排成可投屏的 HTML。

---

## 1. 工具怎么分

| 工具 | 擅长 | 本工序里做什么 | 不要让它做 |
|------|------|----------------|------------|
| **人** | 目的、红线、事实数字 | 写初版「关于什么 / 用来做什么」；拍板大纲页数；和 WorkBuddy **交叉定稿** | 在 pptx 里直接改字 |
| **WorkBuddy** | **文字**（大纲结构、讲稿、口径） | 根据初版拉大纲；扩成三栏定稿；和人来回改到冻结 | 不要在定稿未冻时直接出 HTML |
| **Cursor** | 仓库、HTML/CSS、导出脚本 | **定稿冻结后**生成 `index.html` + `deck.css`、跑导出 | 不要用 Cursor 从零写整本大纲/定稿当终稿 |

```text
人：初版文字（关于 xxx 的 PPT，用来做什么）
        ↓
WorkBuddy：大纲（页数、目录、每页一句话）  ← 文字这一步它更好
        ↓
人 × WorkBuddy：交叉定稿（PPT 上的字 / 口述 / 不上屏）
        ↓
Cursor：HTML 16:9（演示真源）→ 需要时再导出 pptx/pdf
```

---

## 2. 四步（前面加一步「初版」）

| 步 | 产出 | 写什么 | 用谁 |
|----|------|--------|------|
| **0 初版** | 一段说明，可放在 `大纲.md` 文首 | 关于 **xxx** 的 PPT；**用来做什么**（听众、场合、时长、红线） | **人** 先写；可丢给 WorkBuddy 润一版，但目的必须人定 |
| **1 大纲** | `*-大纲.md` 或 `目录.md` | 页数、目录、每页一句话 | **WorkBuddy** 主写；人锁结构 |
| **2 定稿** | `*-定稿.md` | 每页：**PPT 上的字 / 口述 / 不上屏的口径** | **人 + WorkBuddy 交叉**；未冻结不要排 HTML |
| **3 HTML** | `index.html` + `deck.css` | 用定稿排 **16:9** 页 | **Cursor**（演示真源） |
| **4 导出** | `output/*.pptx` · `*.pdf` | Playwright 截图/打印 | **Cursor** 跑脚本；交付件禁止当编辑稿 |

```text
改字路径（唯一）：人/WorkBuddy 改定稿.md  →  Cursor 改 index.html  →  再跑导出脚本
禁止：直接改 pptx / pdf；禁止跳过定稿只改 HTML 里的口号数字
```

---

## 3. 目录怎么放

新建一套 Deck 时，建议一个文件夹收齐：

```text
<deck-name>/
  大纲.md          ← 步骤 1（WorkBuddy）
  定稿.md          ← 步骤 2（人 × WorkBuddy；内容真源）
  index.html       ← 步骤 3（Cursor；演示真源）
  deck.css
  export_pdf.sh
  export_pptx.sh   ← 需要 pptx 时再加
  README.md        ← 预览 / 导出命令
  output/          ← 导出成品（可 gitignore 大文件）
```

仓库里两套对照：

| 步骤 | 转正述职 | 品牌产品介绍 |
|------|----------|--------------|
| 1 大纲 | [`转正述职-PPT大纲-2026.md`](./转正述职-PPT大纲-2026.md) | [`marketing/销售真源/宣讲Deck/目录.md`](../../marketing/销售真源/宣讲Deck/目录.md) |
| 2 定稿 | [`转正述职-定稿目录与简介-2026.md`](./转正述职-定稿目录与简介-2026.md) | [`marketing/销售真源/宣讲Deck/Trinity产品介绍.md`](../../marketing/销售真源/宣讲Deck/Trinity产品介绍.md) |
| 3 HTML | [`转正述职-答辩PPT/index.html`](./转正述职-答辩PPT/index.html) | [`marketing/销售真源/宣讲Deck/index.html`](../../marketing/销售真源/宣讲Deck/index.html) |
| 4 导出 | `转正述职-答辩PPT/export_pptx.sh` · `export_pdf.sh` | `marketing/销售真源/宣讲Deck/export_deck_pdf.sh`（目前只出 PDF） |

品牌 Deck 的定稿目前是 **页上 + 备注（销售说）** 两栏，没有单独的「不上屏口径」。新 Deck **按下面三栏写**；外发红线也写进「不上屏」。

## 4. 步骤 0 · 初版文字（交给 WorkBuddy 之前）

人先写清这三句，再丢给 WorkBuddy。没有「用来做什么」，大纲会写成万能模板。

```markdown
# <Deck 名称> · 初版

关于：要写一套 **xxx** 的 PPT。
用来做什么：场合 / 听众 / 时长 / 希望对方听完做什么（试用、答辩通过、上架评审……）。
已有材料：仓库路径、旧稿、红线（不写成本、不点名竞品……）。
不要写成：……
```

交给 WorkBuddy 时附带本范例的大纲模板，并写明：**先只出大纲，不要直接定稿、不要 HTML。**

---

## 5. 步骤 1 · 大纲模板（WorkBuddy 主写）

把下面复制成 `大纲.md`。页数先估、目录先锁；一句话用来判断「这一页能不能删」。

```markdown
# <Deck 名称> · 大纲

> 听众：
> 时长：约 __ 分钟
> 页数：约 __ 页（16:9）
> 主轴（一句话）：
> 红线（不写 / 不点名）：

## 目录

| 页 | 章节 | 标题 | 一句话 |
|----|------|------|--------|
| P01 | 开场 | 封面 | |
| P02 | … | 目录 | |
| P0n | 收尾 | 联系 / 致谢 | |

## 阅读路径（可选）

只关心 A  → P01–P0x 即可停
只关心 B  → P01–P04 → P0y–P0z
```

**过关**：每页都能用一句话说完；相邻页不抢同一句结论。

---

## 6. 步骤 2 · 定稿模板（人 + WorkBuddy 交叉）

大纲锁页之后，**不要直接灌 HTML**。定稿和 WorkBuddy 来回改：人补事实数字与红线，WorkBuddy 收口上屏字数、口述节奏、不上屏口径。双方都认了再标「冻结」。

把下面复制成 `定稿.md`。**一页一段，不要把全书揉成一篇散文。**

文首写清：听众、时长、页数、主轴、版本（草稿 / 冻结）。

```markdown
## 第 N 页 · <标题>

**PPT 上的字**（限约 6 行 / 一张表；观众 3 秒能扫完）

- 标题：
- 要点：
- （可选）右侧卡片 / 对照表：

**口述**（不读 PPT；写秒数，如 20～40 秒）

> 讲的是故事和判断，不是把上屏字再念一遍。

**不上屏的口径**（Q&A / 红线 / 数字怎么解释）

- 能说但不能上屏：
- 禁止说 / 禁止写：
```

| 栏 | 用途 | 常见错误 |
|----|------|----------|
| **PPT 上的字** | 投屏骨架 | 把口述全文贴上去 → 满屏 |
| **口述** | 现场讲 | 与上屏逐字重复 → 听众走神 |
| **不上屏** | 答辩/销售备着 | 数字口径两套（上屏 16 家、嘴上 800 条线路却不解释） |

品牌介绍可把「口述」写成「备注（销售说）」；对外 Deck 仍建议保留「不上屏」（成本、未拍板折扣、竞品名）。

**过关**：上屏能单独当海报；口述能单独当逐字稿；不上屏能挡住乱承诺。

---

## 7. 步骤 3 · HTML（Cursor，演示真源）

定稿冻结后 **交给 Cursor** 排，不要用 WorkBuddy 写整页 HTML。约定：

1. **比例**：`--slide-w: 13.333in; --slide-h: 7.5in;`（16:9）
2. **一页一个** `<section class="slide" id="p01">` … `p0n`
3. **工具栏**写明内容真源文件名，例如：`内容真源：定稿.md`（打印/截图时 CSS 隐藏 `.toolbar`）
4. **上屏字只来自定稿「PPT 上的字」**；口述、不上屏不进 DOM
5. 版式可复用现成 `deck.css`（述职或 brand-deck），不要另起一套无文档的色值；品牌向页面优先 `var(--*)` / 现有 deck token
6. 本地预览：`open <deck>/index.html`

最小骨架：

```html
<div class="toolbar">
  <p><Deck 名称> · N 页 · 16:9（内容真源：定稿.md）</p>
  <a href="#p01">回封面</a>
</div>
<div class="stage">
  <section class="slide" id="p01">…</section>
</div>
```

**过关**：浏览器里每一页都刚好一屏、不滚动；字号在投影下仍可读。

---

## 8. 步骤 4 · 导出（Cursor 跑脚本）

| 交付 | 做法 | 仓库样例 |
|------|------|----------|
| PDF | Playwright `page.pdf`，宽 13.333in × 高 7.5in，`print_background` | `export_pdf.sh` / `export_deck_pdf.sh` |
| PPTX | 逐页截 `.slide` 铺满 16:9 幻灯片（**位图**，PPT 里不能改字） | `转正述职-答辩PPT/export_pptx.sh` |

脚本注释里写死一句：**页为位图，改字回定稿 → HTML，不要在 PowerPoint 里改。**

`output/` 只当投屏包 / 发附件；Git 里大 PDF 按各 Deck 的 `.gitignore` 处理。

## 9. 给 AI 的派活（复制即用）

### 9.1 交给 WorkBuddy（文字：大纲 / 定稿）

初版写完后出大纲：

```text
按《讲解Deck-四步生成范例》步骤 1，根据下面初版写大纲。
先只交：页数、目录、每页一句话。不要定稿、不要 HTML。
关于：要写 xxx 的 PPT。
用来做什么：……
听众 / 时长 / 红线：……
```

大纲过了，交叉定稿：

```text
按范例步骤 2，把大纲扩成定稿：每页「PPT 上的字 / 口述 / 不上屏」。
我们交叉改，你出一版我改口径，再收一版。不要排 HTML。
数字以仓库现行口径为准，待补处标「待补」。
```

### 9.2 交给 Cursor（HTML / 导出）

定稿冻结后再排版：

```text
定稿已冻结（人 + WorkBuddy 交叉完成）。按《讲解Deck-四步生成范例》步骤 3，
用定稿灌 16:9 HTML（可复用 brand-deck 或转正述职的 deck.css）。
上屏只取「PPT 上的字」；口述和不上屏不要进页面。不要重写大纲或定稿措辞。
```

改一页字（文字仍回人 / WorkBuddy 改定稿，Cursor 只同步页面）：

```text
定稿第 N 页已改。只同步 index.html 对应 section。不要改 output 里的 pptx/pdf。
```

## 10. 检查清单

- [ ] 初版写清：关于 xxx、用来做什么、听众、红线
- [ ] 大纲由 **WorkBuddy** 主写，页数稳定，每页有一句话
- [ ] 定稿由 **人 + WorkBuddy 交叉**，每页三栏齐全（或明确两栏 + 文首红线）
- [ ] 相邻页结论不重复；定稿已标冻结
- [ ] **HTML 用 Cursor** 灌，页数 = 定稿页数，`id="p01"` 起连续
- [ ] 工具栏指向定稿文件名
- [ ] 上屏无「不上屏」里的禁写项（成本族、未拍板折扣、假客户名等）
- [ ] 需要投屏包才导出；导出后抽查 1 页字号与表格是否溢出
- [ ] 改字走 定稿 → Cursor 改 HTML → 再导出

## 11. 两套样例差在哪（对照，不另起规范）

| 项 | 转正述职（按本范例做满） | 品牌产品介绍（同一骨架、未做满） |
|----|--------------------------|----------------------------------|
| 大纲 | 独立 `PPT大纲` | `目录.md`（页 + 一句话） |
| 定稿 | PPT / 口述 / 不上屏 | 页上 / 备注（销售说） |
| HTML | 12 页，工具栏写定稿文件名 | 18 页，工具栏链目录 |
| 导出 | PDF + PPTX | 目前以 PDF 为主 |
| 状态 | 定稿冻结后再排 | v4.6 仍标草稿；P16 占位 |

以后新产品介绍要改字：改 `Trinity产品介绍.md` → 同步 `index.html`，不要直接改 PDF。新 Deck 从第一步就按三栏定稿写。
