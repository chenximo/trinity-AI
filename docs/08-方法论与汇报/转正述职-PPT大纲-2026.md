### 第3页 · 行业认知与竞品分析（主线 API）

**为什么做 AI API 聚合**

模型厂商接口、计费、限流各异，企业/开发者多头接入成本高。统一 **OpenAI 兼容网关 + 路由 + 计费** 是明确需求。

**我们和竞品的分野**

- 不做训练、不做自研大模型 —— 做 **路由与商业化层**  
- 对客叙事：**预充值 + 模型绝对价**，不做「中转站额度 × 倍率」主路径  
- 对内有商务洽谈底座，对外有标准报价表 —— **管价 / 报价 / 审价** 产品化，而不只是挂一堆模型

- 国内中转站类：倍率/额度心智重；我们明确 **绝对价 + Credits**

### 第4页 · 从 0 到 1——关键决策复盘

**决策一：预充值 + 绝对价（不做订阅制主路径，不做倍率主叙事）**  
API 天然按量；用 Credits 入账按模型单价扣。避免「中转站倍率」心智；与竞品对照后锁口径。

**决策二：对内 L3b / 对外 L3a 拆开**  
成本、GM、线路只进对内商务总册；对外只发标准报价绝对价。销售有武器，成本不外泄。

**决策三：刊例写回必须人确认，且本轮只上浮**  
经营安全优先于「全自动改价」。自动化做出包与确认单，**写价仍是人**。

**决策四：用量档不自动改运行时单价**  
≥$5k / $10k / $50k 等是洽谈与报价展示；达档是否给折由商务合同/特批，系统不做耗量自动升档。

**决策五：OpenAI 兼容 API**  
换 base_url / Key 即可接入，降低迁移成本 —— 开发者体验底座。

**决策六：官网只讲浅折 + 场景 + 找商务**  
商务深折与证据链不上官网，避免对外口径打架。

**决策七（范围）：GEO 不进本阶段主交付**  
资源集中在 API 可售卖与云品牌叙事；GEO 保持规划。

### 第5页 · 主线成果①：定价与商业化体系（0→1）

**建成了什么**

| 层 | 含义 |
|----|------|
| L0 | 官方价锚 |
| L1 | 进货/上游挂牌 |
| L2 | 线上基础刊例（价审确认后写回） |
| L3a | **对外**标准报价表（可外发） |
| L3b | **对内**商务洽谈折扣底座（勿外发） |

**产品「三件套」**  
① 对内商务底座 ② 广场浅折（自助引流）③ 对外标准报价表  

**对外报价（L3a）**  
- 形态：全模型 × 充值档 **绝对价**  
- 对外档：**≥$5k / ≥$10k / ≥$50k**（表头标「对外」）  
- 目录价 &lt; $5k 档 = 刊例原价展示逻辑（以方案文档为准）  
- **不**自动写生产 `/v1/prices`  

**对内商务（L3b）**  
- 五档洽谈底座（$1k～$50k 等，以总册为准）；底线与最深档已锁  
- 仅内部使用  

**运营产品**  
- 后台：价目预览 / 价格校验 / 商务价格（原型 + 需求清单）  
- 价审：**一点按钮已完成**（触发 → 出包/确认单 → 人确认写价）  

**刊例治理**  
V1 线上快照 / V2 国际站优先；默认跟 V2；写回只上浮。
