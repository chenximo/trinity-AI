## 1. 上服务器要更新什么（部署清单）

上服务器不是「原样拷贝跑起来」就完事，至少要改下面几类。

### 1.1 运行与发布

| 更新项 | 现在 | 上服务器后 |
|--------|------|------------|
| 前端 | `npm run dev` 本机 | `npm run build` → Nginx / 静态托管；API 反代 `/api` |
| 后端 | `uvicorn --reload` 本机 | systemd / Docker + gunicorn/uvicorn workers；关 reload |
| 配置 | 默认推算仓路径 | **环境变量 / `.env` 注入**，禁止依赖开发机绝对路径 |
| HTTPS / 域名 | 无 | 证书 + 内网或 VPN 访问策略 |
| 进程守护 | 无 | 开机自启、日志轮转、健康检查 `/api/health` |

### 1.2 数据库

| 更新项 | 现在 | 上服务器后 |
|--------|------|------------|
| 引擎 | **SQLite** 单文件 | 建议 **PostgreSQL**（或现有 MySQL） |
| 连接 | `OPS_DESK_DB` 文件路径 | `DATABASE_URL` / `OPS_DESK_DATABASE_URL` |
| 迁移 | `CREATE TABLE IF NOT EXISTS` | Alembic / 显式 migration 版本 |
| 备份 | 拷贝 db 文件 | 定期 dump；敏感收款账号纳入备份策略 |
| 代码改动 | `sqlite3` 直连 | 抽象仓储层或 SQLAlchemy；支付出单逻辑不变 |

### 1.3 文件存储（付款申请单 Excel）

| 更新项 | 现在 | 上服务器后 |
|--------|------|------------|
| 落盘 | 本地目录 `AI云业务/发票/付款申请/` | **腾讯云 COS**（或等价对象存储） |
| 下载 | 直接 `FileResponse` 本地路径 | 签名 URL / 后端流式转发 |
| 删除 | `path.unlink()` | COS delete object |
| 配置 | `OPS_DESK_PAYMENT_EXPORT_DIR` | `COS_BUCKET` / `COS_REGION` / `COS_SECRET_*` / `COS_PREFIX` |
| 代码改动 | `payment_form.generate` 写本地 | 增加 `Storage` 接口：`put` / `get` / `delete`；本地实现保留作开发默认 |

### 1.4 主数据与密钥

| 更新项 | 现在 | 上服务器后 |
|--------|------|------------|
| 云厂商收款账号 | SQLite seed（明文） | 配置中心 / 加密字段 / 仅服务端可读；**勿进前端包** |
| 模板 xlsx | 仓内路径读 | 随镜像打包，或 COS 固定 key，或挂载卷 |
| 申请人/部门/付款主体 | `Settings` 默认值 | 环境变量或管理页可改 |

### 1.5 安全（上线最低线）

| 更新项 | 说明 |
|--------|------|
| 登录鉴权 | 至少 Basic/OIDC/内网 SSO 其一；现无登录，**上线前必补** |
| 权限 | 出单 / 删除是否同一角色（建议删除需二次确认 + 审计日志） |
| CORS | 收窄为正式前端域名 |
| 审计 | 出单、删除、清空月记操作人与时间 |

### 1.6 与仓 / 业务目录的关系

| 更新项 | 建议 |
|--------|------|
| 消耗结算 Excel | **仍可不在本工具管**；若服务器要扫表，改为上传 COS 或只读挂载，不强制 git 仓 |
| 历史「星瀚付款单+报销单.xlsx」 | 作模板与一次性导入源；正式环境以库 + COS 为准 |
| Git | 代码进仓；**运行时 db / COS 对象 / 密钥不进仓** |

## 2. 功能迭代（产品）

按优先级排期；部署改造可与 M2 并行，不必等功能全完再上服务器。

### M1 · 出单闭环（✅ 基本完成）

- [x] 公司 × 云 × 金额出付款申请单  
- [x] 预览 / 打印 / 下载  
- [x] 按月列表、删除、清空本月  
- [x] Element Plus 壳  

**残留（M1.1）**

- [ ] 华为云收款主数据补齐后方可出单  
- [ ] 用途别名可配置（远景 / BID / 山河聚量）  
- [ ] 出单前「仅预览不落盘」可选  

### M2 · 可部署底座（上服务器必做）

- [ ] 配置外置（env）：库、COS、模板、付款主体  
- [ ] `Storage` 抽象 + COS 实现；本地实现保留  
- [ ] DB 抽象 + PostgreSQL（或现网库）+ migration  
- [ ] 前端 production build + Nginx 反代示例  
- [ ] Docker Compose（api + web 静态 + db）可选  
- [ ] 登录鉴权（最低可用）+ 操作审计表  

**验收**：内网域名可登录 → 出单 → 文件在 COS → 列表下载 → 删除同步删 COS 对象。

### M3 · 主数据与体验

- [ ] 客户 / 收款方 / 付款主体后台维护页（勿写死 seed）  
- [ ] 从历史 workbook 批量导入旧付款单（可选）  
- [ ] 导出文件命名与用途模板可配  

### M4 · 开票申请（钉钉少填 + 留档）

详见 [`开票申请-产品设计.md`](./开票申请-产品设计.md)。

| 子期 | 内容 | 依赖 |
|------|------|------|
| **N1（建议先做）** | 开票抬头主数据 + 开票记录 + **一键复制**到钉钉 + 按月留档/删除 | 无钉钉权限也可上 |
| **N2** | 钉钉 Spike：能否用 API 创建「开票申请」(`invoiceApplication`) 并带字段 | 开放平台应用 + 智能财务/OA 权限 |
| **N3** | Spike 通过则「一键提交钉钉」；失败则长期走 N1 复制 | N2 结论 |

- [x] N1 开票信息库 + 记录 + 复制（2026-10-10）
- [x] N1.1 月度开票额度 50 万：已用 / 剩余实时更新，超额拦截（2026-10-10）
- [x] N1.2 税控已开票导入 + 消耗台账「去开票 / 已开票」联动（2026-10-10）
- [x] M5 · 收款模块：Trinity USD Invoice 出单 + 国内开票入口（2026-10-10，见 [`Trinity收款-Invoice-产品设计.md`](./Trinity收款-Invoice-产品设计.md)）  
- [ ] N2 Spike 报告（go / no-go）  
- [ ] N3 条件接入钉钉发起  

### M5 · 业务扩展（按需）

## 3. 建议落地顺序

```text
① 继续本机用 M1 付款出单
        ↓
② N1：开票抬头 + 开票记录 + 一键复制（立刻减负）
        ↓
③ 并行：M2 部署底座（COS/库/登录）与 N2 钉钉 Spike
        ↓
④ Spike go → N3 接钉钉；no-go → 维持复制，把时间留给部署
        ↓
⑤ M3/M5 按需
```

**原则**：付款出单与开票留档不绑 Admin；钉钉 API 能接则接，接不上用不丢记录的复制方案托底。

## 4. 环境变量草案（上线时落地）

| 变量 | 用途 |
|------|------|
| `OPS_DESK_DATABASE_URL` | Postgres 连接串（替代 SQLite 路径） |
| `OPS_DESK_STORAGE=local\|cos` | 存储后端 |
| `OPS_DESK_COS_BUCKET` / `REGION` / `SECRET_ID` / `SECRET_KEY` / `PREFIX` | COS |
| `OPS_DESK_PAYMENT_TEMPLATE` | 模板路径或 COS key |
| `OPS_DESK_PAYER_NAME` / `DEPARTMENT` / `APPLICANT` | 付款申请默认抬头 |
| `OPS_DESK_AUTH_*` | 登录方式（待定） |
| `OPS_DESK_CORS_ORIGINS` | 前端域名 |

本地默认保持：`STORAGE=local` + SQLite，开发体验不变。
