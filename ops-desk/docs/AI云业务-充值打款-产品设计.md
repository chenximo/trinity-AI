## 0. 已拍范围（v0.2）

**本模块不管消耗结算。** 只做一件事：

> 选公司 + 上游云 → 填打款金额 → **出付款申请单**（预览 / 打印 / 下载 Excel）→ **按申请月留档**。

说明：模板文件名含「报销单」，但打款实际套用的是 sheet **`2.付款申请单`**（员工「报销单」不做）。

| 需求 | 状态 |
|------|------|
| 出单（公司×云×金额）+ 预览打印 + 下载 | **先实现** |
| 按月保留出单记录 | **先实现** |
| 消耗结算 / 服务费 / 余额跑道 | 不在本模块 |

### 0.3 产品形态建议

1. **主数据**：付款主体（星瀚算力）、上游收款方（腾讯/阿里/华为银行信息）、客户别名（hehe↔远景、山河↔BID）  
2. **打款单（Payment）**：一条记录 = 一次申请/一次打款意图  
3. **导出**：按模板 `2.付款申请单` 生成单 sheet 或单文件 xlsx，落盘到 `AI云业务/发票/付款申请/<YYYY>/`  
4. **与消耗台账弱关联**：可选挂「覆盖账期 / 参考消耗」，不强制金额相等

## 1. 背景与现状

### 1.1 业务一句话

面向企业客户转售公有云（阿里云 / 腾讯云 / 华为云）：客户消耗我们侧记结算；我们向云厂商 **预充或补款**，用星瀚主体开付款申请单走财务。

### 1.2 维度

- **客户公司**：hehe（远景侧）、亿点、山河（BID）、星瀚…  
- **上游云**：阿里云、腾讯云、华为云  
- **付款主体（申请单位）**：当前模板固定为 **西安星瀚算力信息科技有限公司**  
- **申请部门 / 申请人**：历史为「星瀚业务部 / 李玲」（可配置）

### 1.3 模板结构（星瀚付款单+报销单.xlsx）

| Sheet | 用途 |
|-------|------|
| `填写说明` | 若干「公司名称」备选（远景/极光/点击矩阵…）——偏报销主体备忘，与付款申请「单位名称=星瀚」不同 |
| `1、报销单` | 员工日常费用报销单（**本期不做**） |
| `2.付款申请单` | **空白模板** |
| `亿点腾讯云 9月` 等 | 已填付款申请单（按「客户+云+日期/月」命名的历史单） |

### 1.4 付款申请单字段（从历史单抽象）

| 字段 | 示例 | 规则建议 |
|------|------|----------|
| 单位名称 | 西安星瀚算力信息科技有限公司 | 主数据·付款主体 |
| 日期 | 2026 年 9 月 16 日 | 申请日（可手改） |
| 申请部门 | 星瀚业务部 | 默认配置 |
| 申请人 | 李玲 | 默认配置 |
| 收款全称 | 腾讯云计算（北京）有限责任公司 / 阿里云计算有限公司 | 按云厂商主数据 |
| 账号 | 银行账号 | 按云厂商主数据 |
| 开户银行 | 招商银行 | 按云厂商主数据 |
| 金额小写 | 261594.76 / 300000 | 手填或参考消耗 |
| 金额大写 | 应与小写一致（历史有直接填数字，**产品应生成规范中文大写**） | 系统生成 |
| 汇款用途 | `{客户别名}{云} {月}费用资源费用充值` | 模板句式可配置 |

### 1.5 与「客户结算」的关系

| | 客户结算（消耗） | 充值打款（本模块） |
|--|------------------|-------------------|
| 金额含义 | 实际消耗（+腾讯 2% 服务费） | 打给上游的充值款 |
| 时间 | 业务所属期 `YYYYMM` | 申请日 / 计划打款日 / 实际打款日 |
| 文件 | `{客户}云业务消耗费用.xlsx` | 付款申请单 xlsx |
| 服务费是否支付 | 结算侧字段（另议） | **不等于**是否已向云厂打款 |

## 2. 目标与非目标

### 2.1 目标

1. **可查**：按客户 × 云 × 时间查出所有打款/申请记录与状态  
2. **可开**：从一条打款意图生成合规付款申请单（对齐现模板版式）  
3. **可跟**：草稿 → 已导出 → 已提交财务 → 已打款 → 作废  
4. **可关联**：可选关联消耗账期，便于假期前「跑道」判断时对照已充未耗  

### 2.2 非目标（v1）

- 不替代财务审批系统 / OA  
- 不直连网银  
- 不自动根据消耗「必须」算出打款额（只提供参考与建议）  
- 不接 Trinity Admin  
- 华为云若暂无完整收款主数据：允许先建厂商占位，收款信息待补后再导出

## 4. 需求清单

### 4.1 R1 记录（P0）

**用户故事**  
作为运营，我希望把每一次「准备打 / 已打」的云充值记下来，以便按公司与上游云查询，避免重复打款和漏打。

**功能需求**

| ID | 需求 | 验收 |
|----|------|------|
| R1.1 | 新建打款单：客户、云厂商、金额、申请日、用途、可选覆盖账期、备注 | 保存后列表可见 |
| R1.2 | 列表筛选：客户、云、状态、申请日区间 | 组合筛选正确 |
| R1.3 | 状态流转：`草稿` → `已导出` → `已提交` → `已打款`；可 `作废` | 非法跳转有提示；作废需备注 |
| R1.4 | 展示汇总：当前筛选下金额合计 | 与列表一致 |
| R1.5 | 主数据维护：客户别名、云厂商收款信息、付款主体默认值 | 可选中并带入新建表单 |
| R1.6 | 历史导入（P1）：从现有 `星瀚付款单+报销单.xlsx` 各付款 sheet 批量导入为已打款/已导出记录 | 条数与关键字段对齐抽检 |

**字段（打款单 Payment）**

| 字段 | 必填 | 说明 |
|------|------|------|
| id | 系统 | |
| customer_id | Y | 关联客户（hehe/亿点/山河/星瀚…） |

## 6. 状态机

```text
草稿 ──导出──► 已导出 ──交财务──► 已提交 ──出纳打款──► 已打款
  │               │                │
  └──────────── 作废 ◄─────────────┘
```

- **已打款** 必须有 `pay_date`（或允许同日默认）  
- **作废** 不可再导出；已导出文件不自动删，仅标记作废
