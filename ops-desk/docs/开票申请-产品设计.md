# 开票申请 · 产品设计（Ops Desk）

> **目标**：少手填钉钉「开票申请」；开票信息可复用；开票记录可查。  
> **原则**：能对接钉钉 API 则代填/发起；对接不上则 **后台维护开票信息 + 一键复制 + 本地留档**。  
> **状态**：草案 v0.1 · 2026-10-10  
> **关联**：[`迭代计划.md`](./迭代计划.md)

---

## 1. 诉求（已确认）

1. 希望通过 API 完成现在钉钉里**手动填写**的部分，避免每次重填。  
2. 若 API 做不了 / 权限不够：在 Ops Desk **维护开票信息**，用时复制到钉钉即可。  
3. **开票记录要保留**（谁、何时、开给谁、金额、票种、是否已提交钉钉等）。

不管走哪条路，**(3) 留档**都做；**(1)(2)** 是递进方案。

---

## 2. 钉钉侧能力判断（对接可行性）

| 能力 | 开放情况（据钉钉开放平台公开文档） | 对我们的含义 |
|------|-----------------------------------|--------------|
| 智能财务套件含「开票申请」 | 流程标识 `dingtalk.businessFinance.invoiceApplication` | 属于 OA/智能财务审批套件 |
| 通用 OA：发起审批实例等 | 有（常需应用权限；部分能力挂 **OA 审批高级版 / 专享 API**） | **有可能**用 API 创建「开票申请」草稿或实例并带控件值 |
| 发票夹：上传/查可用发票等 | 有独立发票相关 API | 偏「票夹/进项」，**不等于**代填「开票申请」审批页 |
| 税控直开（无审批直接出票） | 一般不在开放平台一键搞定 | 不作为目标 |

**结论（产品口径）**

- **不是**「绝对没有接口」——审批/智能财务方向有对接口子。  
- **但也不是**「保证能代填你截图里每一个控件」——依赖：企业是否开通对应版、应用权限、开票申请表单 schema（关联客户/应收等控件往往要先有主数据 ID）。  
- 落地前要做一次 **Spike（1～3 天）**：用测试应用试「创建 process_instance / 智能财务开票申请」能否写入关联客户、是否已收款、开票明细、票种、总额。  
  - Spike **成功** → 走路径 A（API 发起/预填）  
  - Spike **失败或成本过高** → 走路径 B（信息库 + 复制），记录仍做  

Spike 不通过不阻塞路径 B。

---

## 3. 两条路径

### 路径 A · API 代填 / 发起（理想）

```text
Ops Desk 选客户 → 填开票金额/票种等
       ↓
调用钉钉 API 创建「开票申请」实例（或打开带参审批）
       ↓
人在钉钉里点提交/审批（仍可能要人点一下）
       ↓
Ops Desk 记一条开票记录（含钉钉 instanceId）
```

**仍可能保留的人工**：审批人操作、关联应收在钉钉侧校验失败时的补选。

### 路径 B · 开票信息库 + 复制（保底，建议先做）

```text
Ops Desk 维护：客户开票抬头（名称/税号/地址电话/开户行账号等）
       ↓
新建开票记录：选客户 → 自动带抬头 → 填金额、票种、备注
       ↓
「一键复制」整段给钉钉粘贴（或分字段复制）
       ↓
人在钉钉提交；Ops Desk 标记「已提交钉钉」并留档
```

**价值**：不依赖钉钉权限排期；立刻减少重复抄抬头；记录完整。

## 4. 需求清单

### 4.1 开票主数据（P0 · 路径 B 核心）

| ID | 需求 | 验收 |
|----|------|------|
| I1.1 | 维护客户开票信息：抬头名称、纳税人识别号、地址电话、开户行、账号、默认票种、备注 | CRUD |
| I1.2 | 与 Ops Desk「客户」（山河/亿点/hehe…）关联；可一对多抬头（少见） | 选客户带出默认抬头 |
| I1.3 | 列表可搜；单字段 / 整段「复制到剪贴板」 | 浏览器复制成功提示 |

### 4.2 开票记录（P0 · 两条路径都要）

| ID | 需求 | 验收 |
|----|------|------|
| I2.1 | 新建记录：客户、抬头快照、开票金额、票种、是否已收款、关联说明、申请日 | 保存后列表可见 |
| I2.2 | 状态：`草稿` → `已复制/待提交` → `已提交钉钉` → `已开票`；可作废 | 可筛选 |
| I2.4 | **月度开票额度**：默认 58 万/月；优先按不含税金额汇总 → 已开出 / 占用中 / **剩余可开**；超额禁止新建 | 开票页顶栏实时刷新；`OPS_DESK_INVOICE_MONTHLY_QUOTA` 可改 |
| I2.3 | 按月列表；支持删除（测试用） | 同付款申请体验 |
| I2.5 | **与消耗台账联动**：`AI云业务/客户结算` 明细行显示未开票/开票中/已开票；「去开票」按结算总金额生成草稿并回链；可仅标记已开票 | 消耗台账操作列 |
| I2.6 | 导入税控已开票（数电票号 / 价税合计 / 不含税） | 启动幂等种子 + `/api/invoices/seed-issued` |
| I2.7 | 可选附件：钉钉截图 / PDF 发票（本地或 COS） | P1 |

### 4.3 钉钉 API（P1 · Spike 通过后）

| ID | 需求 | 验收 |
|----|------|------|
| I3.1 | Spike 报告：能否创建开票申请实例及字段映射表 | 文档结论 go/no-go |
| I3.2 | go：从记录一键「提交到钉钉」；回写 instanceId | 钉钉侧可见审批 |
| I3.3 | 失败降级：提示改走复制 | 不丢本地记录 |

## 5. 字段建议（开票记录）

| 字段 | 说明 |
|------|------|
| customer_id | 业务客户 |
| buyer_name / tax_no / address_phone / bank_account | 抬头快照（防主数据后改） |
| invoice_type | 专票/普票等 |
| amount | 开票总额 |
| payment_received | 是否已完成收款（对齐钉钉必填） |
| purpose / remark | 开票内容说明 |
| apply_date | 申请日 |
| status | 见上 |
| dingtalk_instance_id | 路径 A 有则填 |
| export_text | 生成的「可复制全文」缓存 |

**一键复制全文示例**（可配置模板）：

```text
购方名称：…
纳税人识别号：…
地址、电话：…
开户行及账号：…
开票金额：…
票种：…
是否已收款：…
备注：…
```

## 6. 与「付款出单 / 消耗台账」关系

| 模块 | 方向 |
|------|------|
| 付款申请 | 我们 → 云厂商打款 |
| 开票申请 | 客户 → 要票 / 我们向客户开票 |
| 消耗台账 | `客户结算/*.xlsx` 明细；**开票金额来源**（结算总金额），状态回写已开票 |

可共用「客户」主数据。推荐路径：消耗台账 → 去开票 → 复制到钉钉 → 标记已开票。  
导航：`出付款申请` | `开票信息` | `消耗台账`。
