# AI 云业务

与 `marketing/`、`pricing/` 齐平。AI 云转售相关商务结算、凭证与打款材料。

**日常操作请走 Ops Desk**（[`../ops-desk/`](../ops-desk/)）：消耗预览/导出、开票留档、付款申请出单。本目录逐步变为 **数据与凭证仓**，不再当主工作台。

API 聚合价目 / Seedance 等大客户对账仍在 [`pricing/账单对账/`](../pricing/账单对账/)。

| 目录 | 现在 | 后续 |

| [`阿里云对账/`](./阿里云对账/) | 同上 | 可只读归档 |
| [`华为云对账/`](./华为云对账/) | 同上 | 可只读归档 |
| `账号备忘录.xlsx` 等 | 备忘 | 主数据以 Ops Desk（客户/抬头/收款方）为准后可收敛 |

## 现在还不能「全部不要」的原因

Ops Desk **尚未完全自持数据**，仍依赖本目录：

1. **消耗**：读 `客户结算/{公司}云业务消耗费用.xlsx`（明细 → 台账）  
2. **付款申请**：写 `发票/付款申请/YYYY-MM/`，模板来自 `发票/星瀚付款单+报销单.xlsx`  
3. **财务凭证**：税控票 PDF/历史单等仍可能只在 `发票/` 里，平台只留了开票记录元数据  

所以：**工作流可以都在平台做；文件夹还要当仓库用一段时间。**

## 建议收敛节奏

| 阶段 | 做什么 | `AI云业务` 怎么变 |
|------|--------|-------------------|
| **现在（已基本到达）** | 日常只开 Ops Desk；少直接翻对账子目录 | 三云历史对账目录标归档；手改只动 `客户结算/` |
| **下一阶段** | 消耗在平台维护（录入/导入）→ 库或受控导出 xlsx | `客户结算/` 变为导出备份或只读快照 |
| **部署期** | 付款单/附件上 COS；库换 Postgres | 仓内 `发票/付款申请` 可不再作为生产落盘 |
| **稳定后** | 历史对账 zip 冷存；README 只留客户结算约定 | 大目录可迁出 git（LFS/网盘），平台不依赖本机路径 |

## 客户结算（当前约定）

一公司一张表：`客户结算/{客户}云业务消耗费用.xlsx`。结构与口径见 [`客户结算/README.md`](./客户结算/README.md)。

新月数据：继续维护该表（或将来在平台录入后回写/导出），**不要**再往 `腾讯云对账/` 等历史目录加新表。
