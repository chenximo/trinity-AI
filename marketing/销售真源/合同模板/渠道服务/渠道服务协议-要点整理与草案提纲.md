## 2. 手写备忘 · 可进协议的要点（已清洗）

1. **渠道对接人员**：全程参与商务拓展，并处理客户侧商务对接问题  
   （协议用语建议：「渠道指定对接人」）
2. **返点约 1% 起步**，以**客户最终结算单**为核算依据  
3. **按客户实际消费**据实返点（强调可核对、非口头预估）

> 备忘页底内部演算数字**一律不写入合同**，仅作内部沟通痕迹，不对外、不对渠道展示。

---

## 3. 条款方向（进协议）

### 3.1 合作内容与义务

- 乙方指定对接人全程参与 Trinity AI 相关商务拓展与客户侧对接  
- 甲方提供结算所需对账口径，并按约支付返点  

### 3.2 返点（核心）

| 项 | 当前口径 | 协议需固化 |
|----|----------|------------|
| 比例 | **约 1% 起步** | 固定 1%，或「不低于 1%」、是否含税 |
| 基数 | 客户**最终结算单** / **实际消费** | 与平台账单或对客结算单哪一字段对齐 |
| 币种 | 未写 | 默认 CNY；外币客户如何折算（只写规则，不写内部演算表） |
| 除外 | 未写 | 退款、冲正、未回款、测试用量等 |

### 3.3 对账与支付（备忘未写，草案预留占位）

- 对账周期（可与平台对账期对齐，如每月 1–10 日核上月）  
- 返点确认后支付日（T+N）  
- 发票（渠道是否开票、税种）与收款账户  

---

## 4. 运营对齐（内部，非合同附件）

```text
Trinity AI 客户用量 / 账单
        ↓
对客结算确认（或平台结算单）
        ↓
渠道返点基数（取「实际消费」或「结算总金额」——签约时写死）
        ↓
渠道对账单 → 支付返点
```

Ops Desk「合同管理」后续可增加渠道协议样板 key（如 `trinity-ai-channel`）。

## 5. 建议协议结构

《Trinity AI 模型服务渠道合作协议》

| 章 | 内容 |
|----|------|
| 一、定义 | Trinity AI 模型服务、渠道方、指定对接人、结算单、实际消费、返点、账期 |
| 二、合作内容与义务 | 全程参与拓展与客户侧对接 |
| 三、返点 | 比例、基数、除外、含税口径（**不含内部系数表**） |
| 四、对账与支付 | 周期、确认、发票、支付 |
| 五、保密与客户归属 | 按需 |
| 六、期限与终止 | 含已产生返点结清 |
| 七、违约与争议 | 管辖地、适用法律（主体定后写） |
| 附件一 | 渠道商信息 / 收款账户 / 对接人 |
| 附件二 | 返点对账表示例（字段级，无可选内部数字） |
