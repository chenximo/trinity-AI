### P03 · 企业 AI 数字化，卡在两端

- **页上**  
  - 导语：难的不是找到云/模型，而是**多渠道分散**带来的接入、运维与管理损耗  
  - **云上困境**：账号割裂 · 对账开票繁琐 · 议价弱/年框绑定  
  - **AI 接入困境**：标准不一 · 运维权限难管 · 想稳跑怕折腾  
  - 收束：**多云资源集采 + 多模型统一 API**  
- **备注**：先共情，不急着推功能。

### P04 · 一篇读懂 Trinity

- **页上**  
  - 面向企业的数字化服务品牌；**AI 云 + AI API**，可独立也可组合  
  - 价值词：统一采购 · 统一接入 · 企业治理 · 可组合交付  
  - 云：阿里云/腾讯云/华为云/AWS/GCP/Azure/**Akamai**；集采、架构、统一账单  
  - API：1 个 API，对话/编程/图/视频；存量系统无需大规模改造  
  - 收束：云上采购更划算 · 大模型接入更简单 · 治理更合规  
- **备注**：立品牌故事，不写能力清单；下一页进入壁垒总览。

## 四、组合与收尾

### P15 · 底层上云 + 上层调模型

- **页上**  
  - 标题：**底层上云 + 上层调模型**  
  - 导语：同一合作关系统一交付（相对只做 API 或只做云）  
  - **双柱 + 配图**：云（多云→工作区）↔ 云+API 汇合 ↔ API（IDE→网关→调度）  
  - **三卡**：客户获得 · 适用对象 · 典型场景（各带小图标）  
- **备注**：品牌前四页讲清组合关系即可；本页是组合客户的展开版。单产品客户可略讲；组合意向客户加重。

### P16 · 常见问题

- **页上**（精选 6 问）  
  1. **和直接调原厂有什么差别？** — 同等模型下，多的是容量、调度、统一协议与治理；详见 P08 对照。  
  2. **现有 IDE / 工具链要不要重配一套？** — 通常不需要大改；兼容入口可直接接入，Claude Code、Codex、OpenCode 等可一键写入网关。  
  3. **数据是否落盘？** — API：纯转发、请求响应不持久化（以正式合规说明为准）；Memory 为本地索引。  
  4. **云和 API 计费是否一套？** — 否；两套口径，勿混用。  
  5. **能否只要其中一个？** — 可以；也可后续升级为组合交付。  
  6. **如何开始？** — 官网注册 / 联系商务；API 可走 Docs 快速联调。  
- **备注**：敏感合规问题以法务/正式文档为准，现场不临场加码承诺。
