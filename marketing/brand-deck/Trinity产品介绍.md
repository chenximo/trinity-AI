## 三、Trinity AI 云（闭环）

### P10 · Trinity AI 云是什么

- **页上**  
  - **一站式多云采购与管理**  
  - 覆盖：阿里云 · 腾讯云 · 华为云 · AWS · Google Cloud · Azure  
  - 相对「企业上官网散买」：集采议价与账期、统一账单发票、上云咨询与对账闭环  
- **备注**：云卖的不是「又一个下单中介」，而是**可运营的多云账号与成本能力**。

### P11 · 功能能力

- **页上**  
  1. **一站式多云采购** — 统一咨询与开通管理  
  2. **集采优惠 + 透明服务费** — 消耗计费 + 固定服务费；不赚差价、无隐性捆绑  
  3. **三大「零」** — 零门槛 · 零保底 · 零承诺（无年框锁定）  
  4. **统一账单与开票** — 灵活开票 / 多抬头；开户续费对账有人跟  
  5. **上云服务** — 咨询、架构与配置推荐、多云成本管控；VIP 响应通道  
- **备注**：功能铺完后，下一页讲壁垒（纳管、账单、双主体、运营后台）。

### P12 · 核心壁垒（重点页）

- **页上标题**：为什么选 Trinity AI 云 · 运营级壁垒  
- **页上金句**：云资源便宜不难买到；难的是多账号、多厂商、多账期并存时，费用看得见、对得上、管得住。  
- **四条硬壁垒**  

  | 壁垒 | 客户获得什么 | 可验证提示 |
  |------|--------------|------------|
  | **多云账号一站纳管** | 工作台看全局，凭据校验与脱敏 | 账号绑定 / 启停 / 审计说明 |
  | **账单聚合与节省可见** | 账期应付、目录价、节省率、厂商占比 | 明细下钻与导出演示 |
  | **双主体余额 + 代充流水** | USD / RMB 分账清晰，贴合跨境与国内并存 | 两套账本隔离，避免硬加总误解 |
  | **安全治理与运营后台** | 加密托管、RBAC、独立云转售管理端 | 权限分级：查看 / 操作 / 导出 |

- **品类对照**

  | 维度 | 分散直连各云（典型） | Trinity 云 |
  |------|----------------------|------------|
  | 账号 | 多控制台、多密钥 | 工作区统一纳管 |
  | 账单 | 各云各口径，手工汇总 | 账期聚合、可导出 |
  | 结算 | 单一路径或线下台账 | 双主体余额 + 代充流水 |
  | 安全 | 凭据散落、审计缺失 | 托管、脱敏、审计与 RBAC |
  | 运营 | 缺专用后台 | 独立云转售管理端 |

- **备注**：双主体结算是「很具体、难随口抄」的点，采购/财务向重点讲。外发不点名其它渠道商。

### P13 · 应用场景

- **页上**  
  - **财务 / 采购**：多云账单发票要对齐，不想每家云各对接一套开户对账  
  - **IT / 架构**：国内云 + 海外云并用，要集采与灵活账期，不要年框保底  
  - **业务负责人**：不只下单，还要咨询、配置推荐、费用与发票有人跟  
- **备注**：按听众选一条深讲；强调「从能卖云到能运营云」。

### P14 · 合作与计费指引

- **页上**  
  - 开通、计费与折扣：**联系商务洽谈专属方案**  
  - 计费原则：**透明**——消耗计费 + 固定服务费；不赚差价、无产品捆绑  
  - 合作流程：咨询 → 方案与报价 → 开通 → 使用与对账 → 售后护航  
  - **三大零**：零门槛 · 零保底 · 零承诺  
- **备注**：明确云**不适用** API 充值档位表。云闭环到此可停。

### P15 · 组合交付（组合壁垒）

- **页上**  
  - **底层上云 + 上层调模型** — 算力与模型入口在同一品牌下谈清、管清  
  - 多数方案只做「聚合 API」或只做「云渠道」；Trinity 可把选型、推理、上云采购与账单落在**一条合作链**  
  - 适合：一边扩云资源，一边把大模型嵌进业务 / IDE / 内容产线  
- **备注**：这是整册「品牌层」最值钱的一句。单产品客户可略讲；组合意向客户加重。

### P17 · 常见问题

- **页上**（精选 4～5 问）

  5. **如何开始？** — 官网注册 / 联系商务；API 可走 Docs 快速联调。
