## 0. 原则（必须遵守）

| 规则 | 说明 |
|------|------|
| **不编造客户名** | 无授权不得写「某大厂 / 某公司已签约」 |
| **早期对外表述** | 页眉或脚注固定：**「场景示意 · 非签约客户案例」** |
| **指标** | 无实测账单时不写具体省钱 %；可写能力与用法 |
| **敏感** | 不写上游成本折、商务深折、内部 GM |

**目标：** 建立「这类客户怎么用 Trinity」的画面；真实 ROI 案例有了再升级为 Case Study。

## 1. 三则场景示意（可直接进 Deck #4 / 案例页）

### 示意 A · 性价比 · 高频对话与批处理

| 项 | 内容 |
|----|------|
| **标题** | 高频调用：用对模型，而不是只用旗舰 |
| **谁** | 有对话 / 批处理 / 轻量 Agent 需求的产品或运营技术团队 |
| **痛点** | 小事也打贵模型；多厂商账号分散，难算清楚花在哪 |
| **做法** | 统一走 Trinity API；场景主推性价比模型（如 Qwen Flash 等，以目录为准）；控制台看用量 |
| **价值画面** | 一套 Key、一份账单；日常流量走性价比带，关键路径再点名旗舰 |
| **证据类型** | 场景示意（待替换为真实账单对比） |

### 示意 B · AI Coding · IDE / Agent

| 项 | 内容 |
|----|------|
| **标题** | 研发效能：IDE 一键接入，模型可换 |
| **谁** | 使用 Cursor / Claude Code 等工具的研发团队 |
| **痛点** | 每个工具一套供应商配置；换模型要改多处；难以给组员分 Key、控额度 |
| **做法** | `trinity-config` / Cookbook 接入；Coding 场景模型（如 gpt-5.3-codex、Qwen Plus 等）；子工作区 + Key + 限额 |
| **价值画面** | 工具侧改一处 Base URL + Key；团队权限与超支风险可控 |
| **证据类型** | 场景示意（待替换为接入工时 / 团队规模数据） |

### 示意 C · 多模态 · 图文与生视频

| 项 | 内容 |
|----|------|
| **标题** | 多模态：同一网关覆盖理解与生成 |
| **谁** | 需要图文理解、生图或生视频能力的业务 |
| **痛点** | 文本一家、视频一家，接口与账单割裂 |
| **做法** | 多模态场景模型（GPT-4o / 5.x、seedance 等，以目录为准）；按量扣 Credits |
| **价值画面** | 业务侧仍是一套集成习惯；视频等能力按刊例清晰计费（**不讲折扣叙事**） |
| **证据类型** | 场景示意 |

## 2. 对外一页版式（示意卡片）

每则示意对外排版建议固定六格：

```text
标题
谁（画像，不写真名）
痛点（1～2 句）
做法（产品能力，不写内部折）
价值画面（结果叙述）
脚注：场景示意 · 非签约客户案例 · 模型以官网目录为准
```

Deck 可用 **一页三列** 压缩 A/B/C；单独 PDF 可一则一页。

## 3. 真实 Case Study 模板（有客户后用）

| 字段 | 填写说明 |
|------|----------|
| 客户（可脱敏） | 行业 · 规模带 · 是否公开品牌 |
| 授权 | 书面/邮件同意引用 |
| 背景与目标 | 上线前怎么接模型、要解决什么 |
| 方案 | 用了哪些 Trinity 能力（API / 工作区 / 限额 / IDE…） |
| 过程 | 接入周期、关键里程碑 |
| 结果 | **可验证**指标（费用、工时、故障、权限事件等） |
| 证言 | 一句可引用原话（可选） |
| 日期与版本 | 案例页版本号 |

**收录门槛（建议）：** 至少 1 个可验证结果数字或明确「上线前后」对比；否则继续用场景示意。
